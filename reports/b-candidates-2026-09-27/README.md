# T6·B 후보 프로젝트 목록 (메타데이터만)

작성일: 2026-09-26. [주입 결함 평가 설계](../../docs/injection_evaluation_design.md) 2.3절의 후보 목록이다. **어떤 저장소도 clone하거나 파일을 열지 않았다.** 쓴 정보는 GitHub 검색 결과의 저장소 이름과, 저장소 메타데이터(별 수, 마지막 push 시각, 포크·보관 여부, 기본 브랜치, 대표 언어)뿐이다. 따라서 이 목록에 있는 프로젝트는 아직 "처음 보는 프로젝트"다.

## 출처

1. **저장소 검색:** `language:Circom fork:false stars:>=10 pushed:>=2023-01-01`, 별 순 정렬. 결과가 59개뿐이었다. GitHub는 저장소마다 가장 많은 언어 하나만 대표 언어로 붙이므로, Circom 폴더가 있는 TypeScript·Solidity 모노레포(실제 대형 프로젝트 대부분)가 빠진다. 이 결과도 버리지 않고 합친다.
2. **코드 검색:** `"component main" extension:circom`. 검색 결과는 29,056개 파일이지만 API는 검색 한 번에 1,000개까지만 돌려준다. 그래서 파일 크기(`size:`) 구간을 반씩 나눠 각 구간이 1,000개 이하가 될 때까지 쪼개서 받았다. 한 바이트 폭까지 좁혀도 1,000개가 넘는 구간은 앞 1,000개만 받았다. 저장소 이름만 모으고 파일 내용은 쓰지 않았다.
3. **팀원 추천:** 팀원이 같은 조건(코드를 돌리거나 깊게 분석하지 않고, README·폴더 구조·`pragma` 줄만 확인)으로 찾아 준 저장소를 `team_recommendations.json`으로 받아 합친다. 저장소 이름만 쓰고, 기준은 다른 출처와 똑같이 적용한다.

검색 출처의 원본 응답은 ignored `runs/b-candidates-2026-09-27/raw/`에 있다. 검색 결과는 시간에 따라 바뀌므로, 재현의 기준은 검색을 다시 하는 것이 아니라 여기에 고정한 목록이다.

## 기준과 제외

- 포크가 아니다. 보관(archived) 상태가 아니다.
- 별이 10개 이상이다. 실습용 저장소를 줄이기 위한 기준이다.
- 2023-01-01 이후 push가 있다. circom 2 프로젝트일 가능성을 높이기 위한 기준이다.
- [B 전용 제외 스냅샷](../../datasets/exclusions.injection-eval.draft.json)의 30개와 이름이 같으면 뺀다. 같은 계열(바이트가 같은 `.circom` 파일) 판정은 파일을 열어야 하므로, 적격성 검사 때 목록 순서대로 적용한다.

## T6·B 분할

**분할은 팀원 추천 마감 뒤에 `build_candidates.py --finalize`로 한 번만 계산한다.** 순서가 후보 목록 전체의 해시로 정해지므로, 목록이 바뀌면 순서도 바뀌기 때문이다. 그 전의 `candidates.json`은 후보와 개수만 담은 임시본이다.

사람이 seed나 순서를 고르지 않도록, 후보 목록 전체의 SHA-256(`candidate_list_sha256`)과 저장소 이름을 이어 붙인 값의 SHA-256 오름차순으로 순서를 정한다. 앞의 `floor(n/3)`개는 T6 풀, 나머지는 B 풀이다. B는 탐색 완전성, 결함 주입, 검증까지 통과해야 해서 탈락이 더 많을 것이므로 더 많이 배정했다.

T6와 B는 각자의 풀에서 **이 순서대로만** 적격성을 검사한다. 부적격이면 사유를 기록하고 다음으로 넘어간다.

## 결과

[candidates.json](candidates.json)에 저장소마다 출처, 메타데이터, 판정을 기록했다(분할 전 임시본). 목록은 [build_candidates.py](build_candidates.py)로 만들었다.

**2026-09-27 수집 결과 (팀원 추천 합치기 전):**

| 단계 | 저장소 수 |
|---|---:|
| 두 검색 출처에서 모은 저장소(중복 제거) | 4,447 |
| 별 10개 미만 | 4,003 |
| 2023-01-01 이후 push 없음 | 87 |
| B 전용 제외 스냅샷과 이름이 같음 | 20 |
| 보관 상태 | 6 |
| **후보** | **331** |

- 코드 검색은 크기 구간 105개로 나눠 페이지 336개를 받았고, 한 바이트 폭까지 좁혀도 1,000개가 넘어 잘린 구간은 없었다.
- 메타데이터는 GraphQL로 100개씩 묶어 받았다. 일시적인 네트워크 오류로 캐시된 1건은 다시 조회했고, 별 10개 미만이라 제외됐다.
- 후보에는 코드 분석기, 컴파일러, 튜토리얼처럼 테스트용 `.circom` 파일만 가진 저장소도 섞여 있다. 메타데이터만으로는 가를 수 없으므로 [설계 문서](../../docs/injection_evaluation_design.md) 3절 0번 기준으로 적격성 검사 때 판정한다.
- 개발에 쓴 결함 데이터셋 `zksecurity/zkbugs`가 후보에 들어 있어서 B 전용 제외 스냅샷에 추가했다.
