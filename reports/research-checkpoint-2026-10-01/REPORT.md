# 연구 진행과 논문용 근거 체크포인트

기록일: 2026-10-01 · 기록 버전: `paper-checkpoint-v1` · 담당: miiz.

**현재 상태:** N3 완료. N4-1의 오프라인 기록·집계 구현, 재현 오류 수정, 두 정상 개발 fixture의 실제 실행을 완료했다. N4-1 전체 비교 가능성 관문은 미완료, N4-2 미착수, N5 미고정이다. 다음 정상 호환성 실험은 **인계 준비 완료·미착수**다. 이 기록은 기존 실행·검토 판정을 바꾸지 않는 후속 종합 기록이다.

**논문 목표:** 실제 entrypoint에서 결함 위치를 사용하지 않고 분석 대상을 자동 구성하는 시스템의 적용성·같은 자원의 검토된 발견 성과·비용을 평가한다. 랭킹은 보조 가설이며 맥락 후보배제는 신뢰성 과제다. 새로 측정한 것은 정상 동작과 준비 비용이다. 새 독립 결함 탐지 성과나 랭킹 우위가 확보된 것은 아니다.

전체 위치는 [논문 근거 색인](../../docs/paper_evidence_index.md), 현재 작업 상태는 [계획](../../docs/plan_revision_2026-10-01.md), 다음 구현·실행 범위는 [정상 호환성 인계](../../docs/next_normal_compatibility_2026-10-01.md)에서 찾는다.

## 2. NE-01·NE-02: 정상 실행과 컴파일 재사용

| 대상 | 독립 fixture 수 | 호출 위치 / 고유 wrapper 구성 | 원본 포함 컴파일: 미재사용 → 재사용 | 정상 경계 일치 |
|---|---:|---:|---:|---:|
| 기존 `ProjectMain(64)` discovery fixture | 1 | 7 / 7 | 16 → 16 | 84/84 |
| 반복·상이 파라미터 산술 통제 | 1 | 5 / 3 | 12 → 8 | 60/60 |

컴파일 수는 **방식별 2회 합계**이며 매번 원본 컴파일을 포함한다. 경계 비교는 대상당 고정 입력 3개를 미재사용/재사용 각각 2회 검사한 합계다. 총 컴파일 **52/52 성공**, 원본 정상 계산 **24회**, wrapper 정상 계산·경계 비교 **144회**, witness R1CS 검사 **168/168 통과**다. 144·168은 독립 회로·프로젝트·원인 수가 아니다.

산술 통제의 원본 포함 컴파일 감소는 `(12-8)/12 = 33.3%`다. wrapper 컴파일만 보면 `10→6`, 40%이므로 어떤 분모인지 반드시 적는다. 재사용 가능한 동일 구성이 없는 기존 fixture의 `16→16`은 대조 결과다. 이 fixture의 시간 변화만으로 재사용 효과가 생겼다고 쓰지 않는다.

두 조건 모두 **같은 현행 discovery/wrapper 생성**을 거쳤다. 이후 호출 위치마다 artifact를 컴파일하는 정책과 완전한 캐시 키별로 컴파일하는 정책을 비교했다. 제품의 과거/현재 버전 전체, 기존 `targets --inspect` 자체, 통째/분할 퍼징 성능 비교가 아니다.

확인 범위는 Circom 2.2.3, `O0`, bn128, scalar `in/out`, 대상당 정상 입력 3개다. 동일 artifact를 공유하면서 호출 위치와 서로 다른 정상 경계 입력을 유지한 사례가 확인됐다. 배열·최적화·임의 입력·일반 프로젝트의 대응은 아직 입증되지 않았다. CPU와 메모리는 미측정이다. 정상 실행 수치는 문제가 발견된 오프라인 집계기를 사용하지 않고 원본 도구 기록에서 산출했다.

**사용 가능한 문장:**

> 두 정상 산술 fixture에서 자동 생성한 wrapper를 실제 컴파일하고 정상 계산을 원본 인스턴스의 경계값과 대조했다. O0와 고정 입력 세 개의 검사 범위에서 144회의 경계 비교가 모두 일치했다. 반복 인스턴스를 포함한 통제에서는 호출 위치를 보존하면서 원본을 포함한 컴파일 횟수가 방식별 두 번 실행의 합계 12회에서 8회로 감소했다.

이 문장을 독립 프로젝트 2개, 일반적 의미 동등성, 취약점 탐지 우위 또는 컴파일 재사용 아이디어의 최초성으로 확대하지 않는다.

## 3. NE-03: 비용 재계산과 해석

아래 값은 원문 표의 소수 여섯 자리 조건별 값에서 계산한 방식별 평균이다. 원문 대표 평균의 마지막 자리와 반올림 차이가 있을 수 있으므로 원문을 수정하지 않았다.

| 대상·구간 | 미재사용 평균(초) | 재사용 평균(초) | 재사용 − 미재사용(초) |
|---|---:|---:|---:|
| 기존 fixture 준비 | 0.1574185 | 0.1508315 | -0.0065870 |
| 기존 fixture 정상 계산·검증 | 10.4299415 | 10.2225585 | -0.2073830 |
| 기존 fixture 두 측정 구간 합계 | 10.5873600 | 10.3733900 | -0.2139700 |
| 산술 통제 준비 | 0.1301375 | 0.0786675 | -0.0514700 |
| 산술 통제 정상 계산·검증 | 7.5618635 | 7.6994215 | +0.1375580 |
| 산술 통제 두 측정 구간 합계 | 7.6920010 | 7.7780890 | +0.0860880 |

계산:

- 산술 통제 준비: `(0.159762+0.100513)/2` 대 `(0.079427+0.077908)/2`.
- 산술 통제 정상 검증: `(7.815336+7.308391)/2` 대 `(7.639796+7.759047)/2`.
- 기존 fixture 준비: `(0.172626+0.142211)/2` 대 `(0.152684+0.148979)/2`.
- 기존 fixture 정상 검증: `(10.377363+10.482520)/2` 대 `(10.141683+10.303434)/2`.
- 두 측정 구간 합계는 해당 방식의 준비 평균과 정상 검증 평균의 합이다.

산술 통제의 준비 감소는 약 **51.47밀리초·39.55%**다. 그러나 정상 검증을 포함한 두 측정 구간 합계는 약 **1.12% 증가**했다. 기존 fixture의 합계는 약 2.02% 감소했다. **어느 차이도 전체 처리시간의 우위·열위를 입증하지 않는다.** 방식별 반복 2회이며 OS 캐시를 비우지 않았고 공유 머신의 모든 활동을 통제하지 않았다. 절대 준비 시간이 짧으며 이 두 fixture에서는 정상 검증 비용이 훨씬 크다.

이 합계조차 소스 snapshot 생성·개발 도구 빌드·버전 조회·최종 보고 비용을 포함하지 않는다. 명칭은 **측정한 준비+정상 검증 구간 합계**로 유지한다. 연구 전체 총비용이나 실제 퍼징의 총비용으로 표시하지 않는다.

**사용 가능한 문장:**

> 산술 통제의 준비 시간은 두 번 실행 평균 0.1301초에서 0.0787초로 감소했지만, 정상 검증까지 포함한 측정 구간의 합계에서는 개선이 관측되지 않았다. 적은 반복과 미통제 시스템 캐시를 고려해 통계적 속도 우위는 주장하지 않는다.

## 4. AG-01: 오프라인 집계 수정 결과

독립 검증은 값 없는 JSON에서 과대 집계·완결성 오류를 재현했다. 후속 수정은 N1–N7을 처리하고 **12개 회귀(집계 7개, 기록 5개)**를 추가했다. 수정 기록에 따르면 새 12개는 이전 snapshot에서 모두 실패하고 수정 후 통과했으며, 기존 record/aggregate 61개는 전후 모두 통과했다. 기존 검증 보고서의 ‘수정 후 수용’ 판정은 그대로 보존했다.

| 검사 시점 | 보고된 결과 | 해석 |
|---|---|---|
| 정상 실행 당시 코드 | Rust 285 통과·22 ignored, Python 경계 테스트 4 통과 | 정상 실행을 수행한 당시 코드·스크립트 검사 |
| 후속 집계 오류 수정 | Rust 297 통과·0 실패·22 ignored, fmt·지정 clippy 통과 | 오프라인 구현 수정 후 검사. 정상 회로 실험을 다시 수행한 결과 아님 |
| 합성 재현 재실행 | A1–A7 등 오류 사례의 기대 결과 변경, 대조 사례 보존 | 보고된 주장을 잘못 승격하지 않도록 한 구조 검증 |

297과 별도 시점의 Python 4를 합쳐 **‘동일 최신 버전에서 301개 통과’라고 쓰지 않는다.** 원문 도구 로그를 이 기록 작성 시 다시 실행하거나 최신 코드 전체를 독립 재검증하지 않았다.

수정 후의 중요한 규칙은 다음과 같다.

- 실행 실패·후보 참조 누락은 완결 음성/원인 0으로 만들지 않는다. `timeout`에서 보고된 후보가 없다는 것과 회로가 안전하다는 것은 다르다.
- 같은 그룹·후보 hash의 상충 판정은 양성 보고의 존재와 미해결 상태를 함께 보존한다.
- 여러 scope의 원인이 한 그룹에서 집계되면 현재 구현은 원인 수를 unknown으로 둔다. 일반적인 별칭·독립성 해석을 해결한 것은 아니다.
- 도구별 검사를 일반 TCCT 원인으로 자동 승격하지 않고, 층간 귀속 충돌을 보존한다.
- 검증 근거를 표현할 필드가 없으므로 국소화 `known(true)`를 현재 거부한다. 이는 근거 없는 승격 방지이며 국소화 정확성 증명이 아니다.

새 주석의 우선순위, 층별 원인 귀속, 실패 시도 재시도·제외, scope 관계는 N5에서 고정할 정책이다. 현재 보수적 처리로 거짓 완결을 막는다. 중첩 증거 내용 검사, 실제 수집의 완전성·시간·원인 연결, 정상/abort 의미 검증, A안 실행 공정성은 남아 있다.

**이번 수정 작업은 완료 기록으로 연결한다. 새 반례나 다음 실험의 실제 차단 문제가 없는 한 또 하나의 포괄 검토를 시작하지 않는다.** 발견된 잔여 한계는 평가 규칙 또는 한계로 관리한다. 이 문장은 구현이 무결함이라는 인증이 아니다.

## 5. 아직 없는 결과와 다음 한 단계

| 질문 | 현재 답 |
|---|---|
| 자동 구성·재사용이 작은 정상 입력에서 작동하는가? | NE-01·02 범위에서는 예 |
| 실제 사용할 최적화·배열에서 신호 대응이 유지되는가? | 미실험. 다음 정상 호환성 실행의 질문 |
| 통째·분할의 결함 후보를 같은 수준으로 확인·귀속할 수 있는가? | 미입증. 정상 동작 결과로 대체하지 않음 |
| 자동 분해가 개발 밖 자료에서 결함을 더 잘 찾는가? | 새 평가 결과 없음. 과거 P2는 개발 동기 관측 |
| 순위가 단순 순서보다 좋은가? | 일반적 우위 미입증. 보조 가설 유지 |
| N4-1 전체·N4-2·N5 상태 | 전체 미완료 / 미착수 / 미고정 |

**다음 작업은 [정상 호환성 인계](../../docs/next_normal_compatibility_2026-10-01.md)의 한정된 실행이다.** 기존 두 scalar fixture와 작은 정상 배열 통제 하나에서 O0/O1 대응을 확인한다. 구현 담당에게 아직 전달·착수됐다고 기록하지 않는다. 새 논문 주장이나 별도 후보 탐색을 시작하는 작업이 아니다.

각 실행은 새로운 파일 경로·버전으로 남기고, 근거 색인에 결과 ID·조건·분모·수치·허용 주장·제한·다음 결정을 한 행씩 연결한다. 정상 호환성 실행은 한 번의 고정 조건표와 필요한 최소 수정으로 끝내며, 지원 밖은 지원 밖으로 남긴다. 같은 입력의 반복을 늘려 독립 사례 수를 키우지 않는다.
