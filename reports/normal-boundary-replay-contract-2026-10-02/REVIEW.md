# 정상 경계 재실행의 사전 수용 기준

2026-10-02 · 버전 `boundary-replay-contract-v1` · 담당 miiz. 병렬로 구현 중인 O0 정상 경계 입력 연결(NB-01)을 판정하기 전에 정한 **사전 수용 기준**이다. **신규 구현을 검증한 보고서나 통과 판정이 아니다.** 작업 중인 구현 파일은 열지 않았다. 근거는 [인계](../../docs/next_step_handoff_2026-10-02.md)의 검토 담당 프롬프트, 완료된 [NC-01 REPORT](../n4-1-normal-compatibility-2026-10-01/REPORT.md)·[SCOPE](../n4-1-normal-compatibility-2026-10-01/SCOPE.md), 기존 [measure_normal_compatibility.py](../../scripts/measure_normal_compatibility.py)와 그 v1 유틸리티다.

**범위와 분모.** 대상은 O0, 기존 정상 fixture 세 개, NC-01에서 고정한 입력 세 개씩이다(입력 계획 SHA-256 `1814314d555c791ede7544c4ae56b225dec633ad8ecc424fce13776f831b7166`). 실행 전 분모는 원본 입력 조건 9개와 경계 45개(호출 경로 7/5/3개 × 입력 3개)다. NC-01 O0와 탐색 결과가 같다면 leaf는 입력 57개, 출력 57개다. 단계별 분모와 상태는 따로 기록한다: 자동 구성 → 입력 연결 → wrapper 정상 재계산 → 제약 검사 → 출력 비교.

상태는 세 가지다.
- **통과:** 대응을 확인했고 값이 일치한다.
- **실패:** 도구 오류, 확인된 불일치, 아래 출처 규칙의 위반.
- **미지원:** 대응을 확인할 수 없다. 이유를 반드시 적는다.

실행하지 못한 항목도 분모에 남긴다. 같은 fixture를 쓰므로 NC-01에 독립 사례로 합산하지 않는다.

## 수용 표

| 항목 | 통과 조건 | 실패·미지원 | 필요한 증거 |
|---|---|---|---|
| 1. 선행 성공과 입력 출처 | 다음이 모두 성공한 입력에서만 경계 입력을 읽는다: 원본 O0 컴파일, 고정 입력의 정상 계산, 원본 witness 전체의 R1CS 검사(exit 0과 `WITNESS IS CORRECT`), export. 읽는 대상은 검사를 통과한 바로 그 witness다. 모든 wrapper 입력 leaf는 입력 ID, 원본 witness 해시, 원본 신호 이름, witness index로 추적할 수 있어야 한다 | **실패:** 원본 단계가 실패했는데 wrapper를 계산함. 원본 입력이 고정 계획과 다름. 출처를 추적할 수 없는 입력. 원본이 실패한 입력의 경계는 ‘원본 불가로 미실행’으로 분모에 남긴다 | 입력 계획 해시. 원본 단계별 명령 ID·종료 코드·witness 해시. 경계별 출처 표 |
| 2. 파라미터·배열 모양·호출 위치 | 경계 단위는 discovery 그래프에서 확장한 호출 경로(prefix) × 입력이다. 이 fixture들에서는 호출 위치와 같다. 구체 파라미터, `instance_key`, 컴파일 단위를 기록한다. 모양은 원본 `.sym`의 `prefix.in[…]`과 wrapper `.sym`의 `main.in[…]` leaf 집합에서 확인하며, 길이와 순서가 같아야 한다. 컴파일 단위를 공유하는 경로(산술 `Step(2)` 3곳, 배열 `VecStep(2,2)` 2곳)도 각자 입력을 읽고 출력을 비교한다. **같은 컴파일 구성의 재사용은 같은 호출 맥락을 뜻하지 않는다** | **실패:** 컴파일 단위나 `instance_key`로 경계를 합쳐 입력이나 비교를 공유함. 다른 경로의 신호를 읽음. **미지원:** scalar·1차원 길이 1–8 밖의 인터페이스. `in`/`out` 밖의 입력·출력 신호. 양쪽 모양 불일치. 선언된 입력 전체를 채울 수 없음 | 경로별 identity, prefix, `instance_key`, cache key, 파라미터, 양쪽 leaf 이름. 재사용 경로마다 출처 witness index가 서로 다름. 산술·배열 통제는 경로마다 경계 입력이 다르게 설계됐으므로, 재사용 경로들이 같은 값을 받으면 경계가 합쳐진 것으로 조사 |
| 3. 수동 공식 비의존 | 입력을 구성하는 경로가 쓰는 정보는 원본 symbol·witness, discovery 경로, wrapper 인터페이스뿐이다. fixture 이름(`case`), 경로별 offset·크기 표, 예외 목록, `adapter()`의 값을 읽지 않는다. 기존 `adapter()`·`oracle()`과 비교하려면 입력을 구성한 뒤 별도 진단 열로만 둔다. 그 비교를 지워도 상태가 같아야 한다 | **실패:** 새 입력 경로가 `adapter()`나 fixture·경로별 분기를 호출함. 진단 대조 결과가 입력·모양·상태를 바꿈. **미지원:** 직접 대응 없이 공식이 있어야 입력을 만들 수 있는 경계 | 입력 구성 함수의 위치·해시·인자 목록, 그리고 그 경로에 `adapter()` 호출이나 fixture별 분기가 없다는 근거. 회귀 검사 두 가지: (a) fixture 이름과 경로 표를 바꿔도 symbol·witness가 같으면 입력이 같다. (b) witness 값을 바꾸면 입력도 따라 바뀐다. NC-01 O0에서 adapter 값이 원본 경계 입력과 모두 같았으므로, 진단 대조에서 차이가 나오면 결함 신호로 조사 |
| 4. 출처 일치와 독립 출력 일치 | 두 증거를 다른 분모로 보고한다. **(i) 전달 확인:** wrapper witness의 `main.in`이 원본에서 읽은 값과 같다. 구성상 같아야 하므로 대응 성과로 세지 않는다. **(ii) 독립 출력:** 입력 신호만 담은 파일을 wrapper 자신의 WASM에 넣어 새 witness를 계산하고, 그 witness가 전체 R1CS 검사를 통과한다. 그다음 `main.out`과 원본 `prefix.out`을 symbol 대응으로 읽어 모든 leaf가 일치해야 한다. 원본 witness는 wrapper 계산에 전달하지 않는다. 경계는 (i)과 (ii)가 모두 성공해야 통과한다 | **실패:** 원본의 출력이나 중간값을 wrapper 입력 파일·witness에 넣거나 복사함. 기대 출력을 공식이나 wrapper 자체에서 만듦. wrapper 제약 검사 실패를 통과로 셈. (i)만으로 경계를 통과시킴. **미지원:** 원본 `prefix.out`이나 wrapper `main.out`을 읽을 수 없음 | wrapper 입력 파일의 해시와 키 목록. wrapper witness 계산·제약 검사 명령. leaf별 입력·출력 상태. 출력이나 기대값을 바꾸면 불일치가 나오는 음성 대조 회귀 검사 |
| 5. 결측·최적화·index·부분 배열·모호성 | 모든 leaf가 일치·불일치·미지원 가운데 하나와 이유를 가진다. 원본 입력 leaf가 하나라도 읽히지 않으면 그 경계의 wrapper 입력을 만들지 않고 미지원으로 남긴다. 이유는 NC-01의 분류를 따르고 모호한 대응을 더한다: `missing_symbol`, `optimized_out_index_minus_one`, `witness_index_out_of_range`, `invalid_field_value`, 모양 문제 | **실패:** 0·기본값·adapter 값·root 출력 별칭으로 값을 채움. 부분 배열로 실행함. 미지원을 일치나 불일치로 집계함. 확인된 불일치를 미지원으로 숨김. 중복 symbol·중복 경로·순환 같은 모호성이 이유 없이 조건 전체를 중단시킴. 이 경우에도 영향받은 분모는 남겨야 한다 | 이유별 개수와 leaf 목록. NC-01 회귀 검사에 더해, 입력 쪽 결측으로 wrapper를 실행하지 않는 경우와 부분 배열 경우의 회귀 검사 |

## 6. 성공 후 주장 범위

**모두 통과하면 쓸 수 있는 문장 하나:**

> 기존 정상 fixture 세 개의 O0와 사전에 고정한 입력 세 개에서, 원본의 검증된 정상 witness로부터 직접 신호 대응으로 읽은 값만으로 호출 경로 45개의 wrapper 입력을 구성했다(fixture별 입력 공식 미사용). wrapper가 독립적으로 계산한 출력은 원본의 해당 경계 출력과 모두 일치했다.

일부만 통과하면 같은 문장에 통과·미지원·실패의 수와 미지원 이유를 붙인다. 원본 입력은 여전히 사전에 고정한 값이므로 ‘수동 입력이 모두 사라졌다’가 아니라 ‘경계 입력 구성의 수동 공식이 사라졌다’로 한정한다. `oracle()`을 남긴다면 원본 점검으로 따로 보고한다.

**쓸 수 없는 주장:**
- 범용 정상 입력 합성
- 모든 입력이나 악의적 할당에서의 의미 보존
- 결함 후보 판정, 통째에서 컴포넌트로의 투영
- 프로젝트 결함, 호출 맥락 판정
- 탐지 우위

다음도 함께 제외한다: O1·최적화·다차원 배열·실제 프로젝트에 대한 지원, NC-01과 합산한 독립 사례 증가, 시간·비용 우위.
