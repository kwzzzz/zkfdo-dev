# N4-1 정상 개발 실행 범위

2026-10-01, 버전 `normal-preparation-v1`, 담당 miiz. 이번 사용자 지시는 집계기 완료와 무관하게 정상 실행을 허용한다. 기록·집계 코드/테스트/문서는 구현 담당 소유로 두고 수정하지 않는다.

- 기존 `tests/fixtures/target_discovery`의 정상 산술 fixture와 결함 없는 작은 파라미터 산술 통제만 사용한다. 후자는 같은 구성의 반복 호출, 다른 파라미터, 중첩 호출을 포함한다. 새 외부 프로젝트·평가 후보·취약점 재현·퍼징은 없다.
- 기존 `targets --no-validate`의 자동 탐색·자동 wrapper를 그대로 이용한다. 원본과 wrapper를 Circom `--O0 --r1cs --wasm --sym --inspect --prime bn128`로 실제 컴파일하고 정상 입력으로 계산한 witness를 snarkjs로 제약 검사한다. 입력/출력 경계는 discovery 호출 그래프와 `.sym`에서 대응을 확인한 경우에만 비교한다.
- 동일 자동 탐색을 유지한 채 artifact 컴파일을 호출 위치마다 수행하는 조건과 컴파일 단위마다 재사용하는 조건을 실제 비교한다. 조건 순서는 각 대상에서 미재사용→재사용 / 재사용→미재사용, 각 2회다. 각 조건은 새 디렉터리·빈 application cache, 순차 실행이며 OS 파일 캐시를 비우지 않는다. 과거 바이너리 전체의 전후 비교라고 부르지 않는다.
- 정상 입력 3개를 고정한다. 준비 시간은 탐색·wrapper 생성과 원본/필요 wrapper artifact 컴파일까지, 정상 계산·제약 검사·경계 비교 비용은 별도 측정한다. 컴파일 실패·시작 실패·timeout, 매핑 실패는 원래 단계에 남기며 수동 성공으로 대체하지 않는다.
- 원본 도구 로그·command/exit/time 기록·입력·witness·컴파일 산출물은 새 ignored `runs/n4-1-normal-execution-2026-10-01/` 하위에 보존한다. 보고에는 경로·도구 버전·해시·판정·실측값만 둔다. `experiment aggregate`로 집계하지 않는다.

정상 입력에서의 계산·제약·경계 일치와 준비 비용만 확인한다. 탐지 우위·일반적인 wrapper 의미 동등성·N4-1 전체 관문·A안 실행 검증의 완료를 뜻하지 않는다. N4-2는 미착수, N5는 미고정으로 유지한다.
