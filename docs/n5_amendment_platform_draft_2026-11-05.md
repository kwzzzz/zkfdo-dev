# N5 플랫폼 개정 초안 — 2026-11-05

상태: **미채택·사람 검토용 초안**. 채택자·채택 시각·적용 실행 목록은 미정이다. 이 파일은 N5 고정 원문, 채택된 10-17 개정, 기존 실행 기록·판정·바이너리를 수정하지 않는다. Ubuntu/AWS에서 N5를 실행할 권한이나 채택된 새 평가 규칙으로 쓰지 않는다.

## 제안하는 적용 관문

1. Ubuntu release·CPU 아키텍처·호스트/이미지 식별자·커널·도구 source snapshot·Cargo.lock·빌드 명령/프로필·실행 파일 SHA를 기록한다. 현재 macOS 바이너리 해시를 Linux 바이너리에 복사하지 않는다.
2. Linux 도구 manifest는 실제 설치·빌드·관측 후 새 measured 판으로 만든다. 현재 `configs/tools.linux.json`은 실행 불가 템플릿이다. N5에 필요한 v1/v2.2 도구도 별도로 명시해야 한다.
3. 먼저 합성 fixture와 허용된 A 개발 자료로 프로세스 회수, 시간/공간/메모리 제한, 후보 기록, J 의미 판정·반례 검증을 확인한다. 이 준비에 held-out 후보를 사용하지 않는다. 판정이 달라지면 원인을 기록하고 해당 플랫폼 적용을 멈춘다.
4. Linux RSS·호스트 사용량·cgroup 메모리·swap·OOM 사건을 각각 이름과 단위로 기록한다. CPU affinity와 메모리 상한은 대상 코드가 시작되기 전에 적용 여부를 확인해야 한다. 적용·감시에 실패하면 감시 없이 계속 실행하지 않는다. 구체 Linux 관문 값과 N5 동시성은 채택판에서 실행 전에 고정한다.
5. UTC·monotonic·suspend-aware 경과와 CPU를 함께 기록한다. suspend/시계 보정, 호스트 경합, 저장 공간 부족, worker 손실을 결과와 분리한다. 재실행 횟수·선정 규칙을 결과 관측 전에 정하고 모든 시도를 남긴다.
6. source/설정/후보/증거의 경로 변경은 새 요청·경로 대응 기록에 남긴다. 기존 고정 요청·instance store·판정 파일을 제자리에서 고치지 않는다. 재사용되는 증거는 다음 요청에서 읽을 수 있는 경로에 리비전 종료까지 보존한다.

새 v5의 개발 비용 비교 모드는 전용 호스트에서 W와 S+J를 같은 조건으로 실행하는 운영 장치다. 이것만으로 N5의 고정 동시3이나 기존 예산·seed·평가층을 변경하지 않는다. Linux에서 적용할 동시성·순서·캐시 정책은 채택판의 명시적 결정 항목이다.

이번 플랫폼 개정에서 바꾸려는 것은 **OS, 도구의 native 빌드, 메모리 관측·강제 방식, 절전이 없는 AWS EC2 운영 조건**이다. 예산 정의와 판정 규칙은 그대로 둔다. EC2는 Mac의 AC·caffeinate·thermal 관문을 그대로 복제하는 대상이 아니지만, 호스트 중단이나 시계 이상을 놓치지 않도록 supervisor의 clock discontinuity 관문은 유지한다.

## Mac–AWS 한 대의 작은 요청 대조

N5에 적용하기 전에 합성 또는 허용된 A 개발 자료에서 작은 저장 요청을 고른다. held-out 후보로 이식 코드를 조정하지 않는다. AWS 인스턴스는 우선 한 대만 사용하고 다음 절차를 별도 영수증으로 남긴다.

1. **같은 요청·seed·도구 소스**를 고정한다. 요청/후보/입력 파일 SHA, 소스 snapshot 또는 commit+patch, Cargo.lock, compiler·빌드 profile, circom/solver/Node/snarkjs 버전을 기록한다. Mac과 Linux native 바이너리 SHA가 다르다는 사실도 각각 기록한다.
2. Mac과 AWS 한 대에서 같은 판정 요청을 각각 새 output·cache·instance-store 조건으로 실행한다. 시간·CPU·자원·설정 영수증을 남기며, 이 대조의 시간을 플랫폼 간 성능 우위로 해석하지 않는다.
3. **verdict, 클래스 구성/판정/사유, 반례 witness의 원본 R1CS Rust·snarkjs 검증 결과**를 비교한다. 원본 산출물 해시나 경로가 달라지는 경우 대응 관계와 의미 검증 근거를 따로 적고, 우선 성공 전략·근거의 변화도 숨기지 않는다.
4. 판정·클래스·witness 검증 결과가 다르거나 도구 소스·설정 대응이 성립하지 않으면 더 큰 요청과 N5 적용을 멈춘다. 원기록을 보존하고 개발 자료에서 원인을 해결한 뒤 새로운 대조 기록을 만든다.

이 절차는 아직 AWS에서 실행하지 않았다. 작은 요청 한 건의 일치만으로 전체 N5 플랫폼 동등성이나 사람 채택을 대신할 수 없다.

## 보존할 판정·평가 조건

대상·예산·seed·L1/L2 정의·상한 숫자·후보 포함 범위·원인 귀속 규칙은 기존 채택 내용을 따른다. 변경이 필요하면 해당 항목과 이유를 별도 새 판에 적는다. 개발 J v2.4의 속도 결과나 Linux 준비 성공은 N5 평가 결과가 아니다. 준비 실패·미완료·감시 실패를 unknown 판정 또는 음성으로 바꾸지 않는다.

새 플랫폼의 비용은 기존 Mac 시간에 이어 붙여 하나의 paired 비교로 만들지 않는다. 플랫폼별 원표와 공통 완료 쌍, 모든 재시도·미완료 비용을 별도로 보고한다. 관측 뒤 빠른 arm만 골라 섞지 않는다. 기존 B 추가분 처리와 새로운 플랫폼 실행의 관계도 사람 채택 시 명확히 정한다.
