## 기존 A에서 실제로 작동한 계산된 입력 경로

[원본 요청 영수증](../runs/n6-j1-2026-10-09.noindex/j-execute.noindex/main/0001/requests/000021/attempt-0001/result.json)의 SHA-256은 `1c476d8ad08198631e7acde0dd37493390fdf62eebe1174fd33ce8aac8a18728`이다. inference-original seed `2026100601`, 요청 `ed23fcef…`, class 3 `main.response_time_normalized_fn[0].division`의 `IntDiv` 입력 둘은 [부모의 Subtract 출력으로 계산](../runs/n6-a1b-2026-10-08/units/inference-original/project/src/responseTimeNormalized.circom)된다. J 기록은 `synthesized_a`, 2라운드, `output_differs`, 최상위 출력 차이 1개, Rust 불만족 0, snarkjs correct다.

보존된 정직/이탈 **O1** witness는 최상위 입력 wire 2,825개가 모두 같고 둘 다 원본 O1 196,096제약을 snarkjs로 통과했다. 기존 요청 폴더에는 이탈 O0 witness만 있었으나, 이번에 **같은 입력 JSON에서 정직 O0 witness를 결정적으로 재생**했다. 새 컴파일의 O0 R1CS SHA `7efa0199…`·SYM SHA `6eecf158…`는 기존 원본과 일치한다. [O0 쌍 영수증 v2](../runs/n5-equal-cost-2026-10-28/o0-pair/o0_pair_receipt_v2.json)(SHA `b08a9457de4de45bbb80668645b89d354834f7f0c67092e92e4bf0015988ebcd`)에서 정직 SHA `afb3de15…`·이탈 SHA `d92fde6c…` 두 witness가 **같은 O0 401,664제약을 snarkjs로 통과**했고, 전체 최상위 입력 2,825 wire는 동일하며 출력 wire 하나(`1`)만 다르다. 따라서 이제 원본 O0에서도 완전한 동일 입력 반례 쌍이다. 기존 [반사실 감사](rq1_inference_causal_review_2026-10-28.md)의 고유 O0 witness 21개 중 이 이탈 witness도 포함되며, IntDiv 한 줄 수정본에서는 `out=quot` 등식 때문에 거부됐다. 새 원인 발견이 아니다.

이 요청의 후보 생성 offset 562.826초 + **해당 J 요청 자체** 124.066초 = 686.892초는 낙관적 하한이다. 실제 기존 J 순차 실행에서는 이 요청이 seed 01의 23개 중 22번째였고 앞선 J 요청 벽시계 합이 569.965초였다. 따라서 S 600초와 그 순서를 합치면 이 결과까지 **약 1,294초 + 준비비용**이다. W 600초 후보 0과 바로 효율 우위를 비교할 수 없다. 아래 W의 seed당 1,236초는 이 개별 사례의 순차 비용보다 약 58초 짧으므로, 이 사례만의 동등 비용 대조라고 주장하지 않는다. [ScaleCirc 원문 대조](scalecirc_primary_comparison_2026-10-28.md)에 따르면 ScaleCirc의 Eq.17도 자식 반례 부모 전파를 제공하나 빠른 경로는 직접 연결 조건이며, 그 밖에는 전체 backend로 돌아간다. 우리의 관측은 **계산된 자식 입력에서 국소 합성 경로가 실제 원본 출력 차이를 만든다**는 구현 증거다. ScaleCirc 전체보다 능력이나 비용이 낫다는 증거는 아니다.

## 별도 W 연장 탐색층

[결과 전 기록](../runs/n5-equal-cost-2026-10-28/protocol_note.md)에서 기존 S 세 seed와 J 요청 시간의 표시값으로 약 3,708초 **하한**을 정하고, W 같은 세 seed에 각각 1,236초(합 3,708초)를 배정했다. 원장 원시값을 다시 더하면 **S 1,800.064178791초 + J 1,907.873374375초 = 3,707.937553166초(세 자리 반올림 3,707.938초)**다. 사전 기록의 3,707.937은 표시값만 더한 반올림 차이로, 배정 3,708초는 바꾸지 않는다. 개별 seed S+J 비용은 1,300.221/1,257.727/1,149.989초여서 seed별 비용 동등이 아니라 **세 seed 합계** 대조다. 원래 W 600초 실행은 세 seed 모두 후보 0, `last_generation=0`, `timeout`이었다. 연장은 이어달리기가 아닌 새 실행이며 N5 본 결과를 바꾸지 않는다. **이 회로는 W 후보 0·S L1을 본 뒤 선택한 유리한 A 사례**이므로 선택 편향이 있다.

세 spec은 [01](../runs/n5-equal-cost-2026-10-28/w-2026100601-1236-spec.json)·[02](../runs/n5-equal-cost-2026-10-28/w-2026100602-1236-spec.json)·[03](../runs/n5-equal-cost-2026-10-28/w-2026100603-1236-spec.json)이다. 기존 v4 실행기 SHA `ff36c6db…`, 고정 zkFuzz SHA `ac2d9d16…`를 쓴다. seed 01의 [사전 컴파일](../runs/n5-equal-cost-2026-10-28/w-2026100601-preflight-escalated/preflight.json)은 성공했다. 첫 시도는 시작 환경 관문을 빠뜨려 중단했고, 중단 중 생긴 고아 zkFuzz가 첫 관문과 재시작에 겹쳤다. 이 두 부분 폴더는 버리지 않고 **분석에서 제외**한다. 전체 프로세스를 종료한 뒤 [깨끗한 60초 관문](../runs/n5-equal-cost-2026-10-28/start-gate-clean.noindex/start-gate.json)(SHA `621f30ba154f7055b9b17a67d4acf3fd26a00fdc3d40fb0b2f2d49619e044ba3`)이 AC·저전력·열·메모리·swap 검사를 모두 통과했고 zkFuzz 중복 프로세스가 없음을 확인했다.

세 새 spec을 원래 W spec과 JSON 키별로 대조하면 변경은 전체·시도 예산 600→1,236초, checkpoint `[600]`→`[600,1236]`, 새 `campaign_id` 네 필드뿐이다. 원본 source/entrypoint, seed, 도구 pin, 10 GiB 메모리 상한은 동일하다.

기존 S 캠페인 완료 뒤 J를 기록된 순서로 처리했을 때 각 seed에서 **첫 L1 요청까지**의 S 600초+J 벽시계 하한은 약 763.168/748.536/703.186초다. 이는 위 계산된 입력 exemplar의 약 1,294초와 다른 요청이며, 준비·사람 검토 시간은 빠져 있다. W 1,236초가 세 seed 모두에서 첫 관측 L1의 실행 시간 하한보다 길다는 점만 이번 시험의 보조 해석으로 쓴다.

세 seed의 원래 600초 본 실행은 모두 0세대·후보 0이었고, 이번 연장 실행은 각각 1세대까지 표시됐으나 **후보 0/3**이다. 유효한 W 시도 실제 벽시계 합은 **3,708.208초**이고 peak footprint 최댓값은 1,478,624,696 bytes다. 원장 세 개의 spec SHA·환경 관문 상태·정상 timeout을 [기계 요약 v2](../runs/n5-equal-cost-2026-10-28/summary_v2.json)(SHA `05f578948474f1041dd960a1691aba541a57f9efca0185750f36e233ad3575ae`)로 대조했다. v1의 0.000001초 반올림 오차는 v2에서 원시값을 재합산해 고쳤고 v1은 보존했다. 종료 뒤 남은 zkFuzz 프로세스는 없다.

**판정:** 기존 S+J의 측정된 *퍼징+J 요청 시간 하한*과 사실상 같은 W 실행 시간을 준 이 A 회로에서 W는 여전히 후보를 못 냈다. 이는 자동 조각 퍼징의 실효성에 유리한 개발 관측이다. inference-original은 W 0·S 양성을 본 뒤 선택됐고 준비·사람 검토 비용이 빠졌으므로, 완전한 동일 총비용 우위·고유 원인 우위·일반화·ScaleCirc 우위로 승격하지 않는다.

**29일 교수님 중간 점검에서 설명할 수 있는 좁은 문장:** “사후 선택한 inference 개발 회로에서 자동 조각 퍼징과 호출 맥락 합성은 계산된 중간 입력의 출력 차이를 동일한 최상위 입력의 원본 O0 witness 쌍으로 확인했다. 전체 회로 zkFuzz는 세 seed에 S+J의 측정 실행 시간 하한과 맞춘 총 3,708초를 줘도 후보를 생성하지 못했다.” 곧이어 “원인은 알려진 IntDiv 계열이고 준비·검토 비용과 독립 B·ScaleCirc 대조는 남았다”고 붙인다. 29일의 목적은 완성 논문 심사가 아니라 **현재 연구 각도와 12월까지의 입증 계획에 대한 교수님 판단**이다.

## ScaleCirc 직접 대조 관문

[공식 아티팩트](https://github.com/jinan789/ScaleCirc#usage)는 자체 벤치마크 배치 명령을 안내하고, [저자 수정 파일 안내](https://github.com/jinan789/ScaleCirc/blob/3d05d0f3e82816135419dba37dde91d48cb65068/modified_parts_to_artifacts/readme.txt)는 Circom 파서 및 Picus/ConsCS 원본 백엔드를 별도로 설치·수정하도록 요구한다. 현재 로컬에 그 전체 구성이 없어 동일 A 사례의 공식 UNDER 경로와 전체 fallback을 지금 즉시 공정하게 실행할 수 없다. 추후 같은 출력 비결정성·입력 계약·총시간에서 공식 구현으로 비교하고, 실행 준비 실패는 우위로 세지 않는다.

이 양성 사례에 대한 외부 반박 의견도 같다. “직접 연결이 아닌 입력에서 **fallback 없이 국소 합성으로 도달**”은 경로 차이지만 ScaleCirc 전체 backend와의 능력·비용 차이는 미검증이다. 당시 반론에서 지적한 정직 O0 쌍 부재는 위의 결정적 재생으로 **해소**했다. 반론의 후속 IntDiv 반사실 재생 제안은 기존 21개 O0 감사에 **이미 포함**됐으므로 반복하지 않는다. 추가 질문은 로컬 증거 식별자를 외부 서비스로 보내는 행위라는 자동 승인 검토에서 거절돼 보내지 않았고 초안은 지웠다.

**확인한 것:** N5/B 현행 상태, A 계산된 입력 사례의 O0/O1 동일 입력 witness 쌍과 원본 전체 검사, 알려진 IntDiv 반사실, W 본 실행의 세 seed 600초 후보 0, 추가 W 세 seed 1,236초·후보 0·1세대·정상 종료, ScaleCirc 아티팩트의 의존성.

**추정한 것:** ScaleCirc 전체 backend 대비 수율·비용, 이 경로의 독립 B 결함 수, 다른 A/B 대상에 대한 일반화. 아직 논문 우위로 주장하지 않는다.
