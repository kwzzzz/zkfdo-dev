# N6-J4 v2.2 수치 상한의 적용 범위 대조 (2026-10-17)

이 기록은 B 판정 전에 J v1 소스 `cb40e3e06c27bfed2dcb19245f5d6b82d1860404`와 J v2.2 소스 `8065e2b7e165ef3f4c1523f240f5d34ecaefdb22`를 `git show`로 대조한 것이다. 대상은 `src/candidate_review/lifting/{mod,repair,synth,predicate,solver}.rs`의 판정 탐색 상한과 호출 경로다. [리드 확인표](../runs/handoff/n6_limit_scope_lead_check_2026-10-17.md)의 일곱 차이(W1–W4 넓힘, N1–N3 좁힘)를 두 커밋의 코드 위치에서 직접 재확인했다. 아래의 “넓힘/좁힘”은 가능한 탐색 경로·질의 횟수에 관한 코드 수준 분류이며, B 판정 결과의 증감을 예측하지 않는다. B 후보 값·witness·판정 결과는 열지 않았다. [J v2.2 고정 기록](n6_j4_freeze_v2_2_2026-10-17.md)(SHA-256 `9ee4126d6036c5f67b8df2d851348028b6764d2b295214b2cef4b9c5d5ba8b88`)은 수정하지 않는다.

## 대조 후 숫자와 적용 경로가 유지된 상한

`repair.rs`의 호출별 최대 반복 6, blanked check 6, abort 인스턴스 선택 6, 경로 깊이/방문 24/20,000, 시작점당 leaf 3, leaf closure 200, hub degree 32, 기본 지역 2,000개, Z3 질의당 10초는 값이 같다. `synth.rs`의 path/try/round 6/12/3, path wire/depth 20,000/48, cone depth/unknown/constraints 6/300/600, joint Z3 20초, 기존 배제 가지 5초와 후보 공유 20초도 값이 같다. `predicate.rs`의 배제 질의 10초·제약 4,000개·전파 8회와 `mod.rs`의 외부 도구 **호출당** 600초도 값과 기존 호출 경로가 같다. 다만 새 repair·small-cone 경로에서 같은 호출당 제한을 받는 호출이 추가될 수 있다. 위 표가 이 동일한 숫자들의 적용 범위 차이를 빠짐없이 구분한다.

코드 위치는 두 커밋의 파일별 1부터 시작하는 줄 번호다. 리드 확인표의 일곱 항목은 W1–W4와 N1–N3으로 모두 위에 대응된다. 시작 상태 순환의 조기 중단은 이 일곱 항목과 별도의 반복 내부 동작 차이로 보존했다. 특히 6개의 abort 인스턴스 선택은 전체 Z3 호출 6회라는 뜻이 아니고, 4,000개 검사는 carry 후 최종 질의 크기의 상한이 아니며, 20초는 경과시간을 차감하는 공유 예산이다. 이 차이들은 중단 관문이 아닌 B 판정 전 방법 기록이다.
