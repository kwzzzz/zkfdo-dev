# C-03 환경 구성·설정 entrypoint 포함 준비 조사 절차 v1

담당 miiz · 기한 2026-10-07. 이 절차와 SHA·고정 시각을 `runs/c03-corpus-2026-10-02/procedure-lock.json`에 남긴 뒤 환경 구성·컴파일을 시작한다. C-02는 무설치 기준의 관측으로 보존하며, 그 수치를 환경이 갖춰진 zkfDO 적용성으로 해석하지 않는다. 변경은 새 버전으로 남긴다.

1. **대상·출처:** C-02 포함 65개와 main 부재로 제외됐으나 순수 JSON Circomkit 설정이 있는 저장소, 팀 CSV 14개를 모두 기록한다. 기존 저장소는 C-02 commit을 재사용하고 새 저장소는 조회한 default HEAD SHA를 고정한다. canonical/이름 변경은 연결하고 fork는 별도 저장소로 유지한다. 주 집계는 HEAD committer date ≥2025-01-01 UTC·명시 라이선스·원본 또는 설정 entrypoint 조건을 적용한다. `team_curated` 14개는 날짜로 제외하지 않고 전부 측정하며, 조건 충족 주 집계·C-02 기존 집합·팀 집합을 각각 제시한다. CSV의 회로 폴더·실사용 근거·Circom 버전 주장, 파일 hash·관측 시각·사본 mtime을 보존한다. 원본 Sheet 수집 시각이 없으면 unknown으로 구분한다.
2. **성격·노출:** 준비 결과와 무관하게 README·topics·팀 사용 근거로 production / library / tool_benchmark / education_example을 분류하고 짧은 근거 문장·경로·hash를 기록한다. 혼합·근거 부족은 unknown으로 보존한다. 저장소 성격은 모든 하위 파일의 production 인증이 아니며 test/example/vendor 경로 역할도 남긴다. 분류를 계측 전에 고정한다. 기존 개발 사용·zkbugs/SoK 노출은 URL뿐 아니라 canonical/rename·fork parent/source·zkbugs 프로젝트명까지 대조하며 직접 일치·계열 연결·불명은 구분한다. 목록상 미노출은 과거 노출 부재의 보증이 아니다.
3. **안전한 자동 환경 구성:** 새 checkout에서 `git submodule update --init --recursive`, 이어 package/workspace root별 lockfile에 맞는 `npm ci --ignore-scripts`, `yarn install --frozen-lockfile --ignore-scripts`, `pnpm install --frozen-lockfile --ignore-scripts`를 실행한다. lockfile이 없으면 `npm install --ignore-scripts` 사용을 명시한다. 도구·설정·생성 lockfile hash, 각 단계 비용·실패를 기록한다. 신뢰한 외부 npm/Yarn Classic/pnpm CLI만 고정해 사용하고 repo의 yarnPath/plugin/pnpmfile·설치 스크립트·Git hook은 실행하지 않는다. manager/lockfile 충돌·비호환·도구 부재는 setup_failure로 남긴다. 자동 단계는 수동 개입이 아니며 소스·의존성 선언·include 수동 수선은 하지 않는다. include는 저장소 루트·root/node_modules·회로 디렉터리 및 결정된 설치 root/ancestor의 node_modules로 산출한다.
4. **entrypoint 고정:** C-02의 알려진 main 파일을 유지하고, 새 저장소·submodule의 버전 관리된 main과 Circomkit JSON의 file/template/params/public(또는 pubs)로 결정적 main을 생성한다. `config_generated` 및 설정 hash·key를 기록하며 설정 JS나 빌드 스크립트는 실행하지 않는다. 경로 탈출·모호성·결측·지원하지 않는 params는 명시적 실패다. 설치로 받은 node_modules의 새 예제 main은 평가 대상을 늘리지 않으며 기존 C-02에 있던 vendor main은 보존한다. 설정 항목과 원본 파일의 중복 연결을 남기고 동일 commit·경로·생성 설정 단위만 합친다.
5. **동일 조건 전후 비교:** 설치 전·후를 같은 Circom 2.2.3/O1/bn128·include 산출 규칙·entrypoint key로 컴파일한다. SHA·설정이 대응되지 않는 항목은 paired 비율에서 분리한다. C-02와의 비교도 별도 표로 남겨 include 규칙 변화와 환경 구성 효과를 섞지 않는다. submodule에서 설치 후에만 발견한 항목은 추가 분모로 남기고 사전 목록 부재를 실패나 성공으로 추정하지 않는다. 이후 기존 `targets` → `experiment prepare --strategy small-first` → `experiment plan --strategy small-first`를 사용한다. zkFuzz/분석기 경로는 존재하지 않는 차단 경로이며 run/lift/후보·witness 실행은 없다.
6. **상태·상한:** 수집/clone 120초, submodule 180초, 설치 root당 600초, 원본 compile 120초, targets/prepare 각 300초(내부 도구 60초), plan 30초, 동시 entrypoint 최대 2개로 고정한다. setup 실패도 후속으로 실행 가능한 단계는 시도하고 setup 영향과 컴파일 실패를 분리한다. 완전 준비는 탐색 미지원 없음·원본과 모든 고유 단위의 준비·wrapper 컴파일·plan 성공을 요구한다. partial은 유효하게 준비된 단위가 있으나 전체 요건 미충족인 경우이며 실패 단위·미지원·누락 이유를 나열한다. 유효 단위 없음은 failed/unsupported, 결측은 unknown이다. 성공 외 모든 상태에 failure_type 또는 미시작 이유를 채우고 복수 사유를 보존한다. timeout·메모리/디스크 부족을 성공 사례로 교체하지 않는다.
