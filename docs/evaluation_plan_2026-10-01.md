# 평가 설계 (2026-10-01)

**설계 단계이며 실행 프로토콜이 아니다.** 현재 방향과 작업 순서는 [계획](plan_revision_2026-10-01.md)을 따른다. 과거 고정 평가의 지표나 판정을 소급 변경하지 않는다.

miiz가 [N3 채택 기록](scope_decision_accepted_2026-10-01.md)으로 보정 범위·주장·고정 방식, 종료 연구 설계 A 우선, 단계 순서·작업 상한과 이번 N4-1 착수 범위를 기록했다. N3는 완료, N4는 진행 중이다. [공통 기록·오프라인 집계](evidence_aggregate_v1.md)의 구현·합성 검증은 완료했으나 N4-1 전체 관문은 미통과다. A안 구현·공정성 검증 완료를 뜻하지 않으며 대상·예산 수치·실행 규칙의 N5 고정은 아직 하지 않았다. 자동 분해 시스템을 주 기여 가설로 유지하고, 랭킹은 보조 가설, 맥락 후보배제는 신뢰성 과제로 둔다.

## 1. 질문

- **RQ1:** 실제 entrypoint에서 자동 구성한 분석이 어느 범위에 적용되며, 전체 회로 분석과 같은 자원·시간에서 검토된 고유 원인과 총비용에 어떤 차이를 만드는가?
- **맥락 판정:** 분해 후보 중 호출 맥락상 배제·미판정·별도 확인 결과는 얼마나 되며, 판정에 드는 비용과 보장 범위는 무엇인가?
- **RQ2(보조):** 사전에 고정한 단순 순서들이 최초 확인 대상 발생시간과 예산 내 결과에 어떤 차이를 만드는가?

이익이 없거나 적용 사례가 적으면 그대로 보고한다. 순위 전략의 우위나 새로운 취약점 발견은 완료 조건이 아니다.

## 2. 대상 모수와 평가 단위

1. 전체 자료 목록과 출처 revision·해시를 먼저 기록한다. 공개 결과의 격리 성공 여부만으로 주 집합을 고르지 않는다.
2. 개발 사용·같은 프로젝트/계열·근거 있는 개발 분리층·불명층을 구분하고, 소스·메타데이터·공개 결과 노출은 따로 기록한다. 주 집합과 보조 집합의 초기 목록·포함 규칙은 새 평가 준비 전에 N5에서 고정한다.
3. 외부 의존성, 옛 문법, 미지원, entrypoint 부재, 루트 결함, 알려진 격리/프로젝트 결과를 각각 별도 열로 남긴다. 경로 이름만으로 production 또는 단일 템플릿 wrapper라고 추정하지 않는다.
4. 새 캠페인 준비 전 전체 모수와 준비를 통과한 부분집합을 함께 보고한다. 과거 준비 이력은 별도 층으로 유지하며 실패·미지원·미판정을 사후 삭제하지 않는다. oracle 적합성에 따른 조건부 분석도 전체 결과와 분리한다.
5. 실행 단위는 **프로젝트·재현 가능한 소스 버전·entrypoint·실행을 바꾸는 설정**으로 생성한다. 기존 commit ID나 자료/파일 해시로 버전을 식별하며 새 git commit은 필수가 아니다. N5에는 초기 목록과 단위 생성·중복 제거·예산 규칙을 고정하고 실제 준비 단위는 그 규칙으로 이후 기록할 수 있다. 라벨·검토 predicate·반복 차이만으로 추가 예산을 주지 않는다.
6. seed 반복은 변동성 측정이며 독립 프로젝트 수가 아니다. 공유 라이브러리와 같은 원인의 중복을 기록하고, 고유 원인·프로젝트/계열 단위 결과를 제시한다.

종전의 원인 5개·프로젝트 3개 목표는 충분한 통계적 검정력을 뜻하지 않는다. 적은 자료에서는 효과 크기·개별 결과·불확실성 중심으로 보고하며 넓은 일반화를 주장하지 않는다.

N1이 확인한 전체 70건과 original 56건은 사례 수이며, 36개 잠재 묶음은 확정 실행 단위 수가 아니다. 지원 가능한 부분집합·원인 수는 별도로 확인한다. 준비 실패·미지원·original 부재를 보존한 공개 벤치마크 평가를 권고한다. 개발 사용, 실행, 준비, 소스 열람, 메타데이터와 공개 결과 지식을 구분하며 기존 미등재 5건·3repo를 미노출로 복원하지 않는다. 개발과 분리된 평가·미노출 일반화 및 과거 준비 이력 처리의 현재 권고는 [결정용 기록 §5](scope_decision_final_2026-10-01.md#5-n5-고정-방식과-평가층)에 있다.

## 3. 비교와 자원

- 주 비교는 동일 entrypoint의 전체 회로 분석과 자동 구성한 분석이다. RQ1 대표 순서는 개발 자료로 사전 고정한다. 결과를 본 뒤 가장 좋은 순서를 대표값으로 고르지 않는다.
- 무작위와 작은 것 우선 같은 단순 순서는 보조 비교 후보로 둔다. 기존 위험/비용 점수와 동적 배분은 주 비교의 필수 조건이 아니다. 최종 전략 수는 비용을 보고 N5에서 정한다.
- 사람에게 정답 위치를 제공받은 격리 결과는 참고 조건이다. 자동 분해와 동등한 기준선이나 이론적 상한으로 부르지 않는다.
- 도구·컴파일러 revision, 설정, seed, 자원 제한, 실행 순서와 동시 실행 수를 기록한다. 경쟁 작업의 영향을 통제하며 벽시계 시간과 사용 자원을 구분한다.
- 전체 회로와 분해에 서로 다른 누락 옵션·화이트리스트 변경을 몰래 적용하지 않는다. 진단용 옵션 비교가 있으면 주 결과와 분리한다.
- 준비·컴파일·캐시·분석 실행·맥락 판정·수동 검토 비용을 분리하고 총비용도 보여 준다. 준비된 상태의 비교와 처음부터의 비용을 혼동하지 않는다.
- SoK의 과거 수치를 같은 환경에서 실행한 기준선으로 취급하지 않는다. 본문/공개 요약의 시간 설정 차이는 미해결이면 명시한다.

600초, 타깃별 30초, seed 3개는 현재 미고정이다. RQ2에서 부족 예산을 따로 만들기 위해 평가 결과를 보고 제한을 줄이지 않는다. 모든 타깃이 시작된 경우도 결과에 남기고 실제 시작 비율과 발견시간을 보고한다.

첫 후보 종료·잔여 예산·재시작과 환경 장애 재시도도 N5에서 사전 고정할 규칙이다. miiz는 [결정용 기록 §3](scope_decision_final_2026-10-01.md#3-비교-수준지표종료-정책)의 공통 총할당 내 반복 시도 A안을 연구 설계로 우선 채택했다. 구현·검증은 별도 필요사항이며 이번 N4-1은 규칙의 기록 형식과 구조적 검증만 다룬다. native-stop은 명시적 대안이며 기존 기능에 따른 자동 선택이 아니다. 할당 소진이 실제 자원 사용의 동등성을 보장하지 않는다. 실제 CPU·벽시계·메모리·대기와 조기 종료·미사용 예산·중복 후보를 보고한다. 이진 성공 지표만으로 첫 미확인 후보 종료의 탐색 기회 차이는 없어지지 않는다.

## 4. 증거와 지표

기존 검토 엔진의 구조적 통과가 사람의 의미 판정까지 증명하는 것은 아니다. 아래 개념은 채택한 설계상의 요구다. N4-1의 [공통 기록 v1](evidence_record_v1.md)은 기존 형식·검토 엔진 출력과의 메타데이터 연결을 구현하고 합성 fixture로 구조를 검증했다. 일반/계약/legacy 층, 컴포넌트·entrypoint TCCT·투영·귀속·완료 상태는 별도로 보존한다. 이 통과를 통째 후보의 의미 검증 성공으로 세지 않는다. [오프라인 집계 v1](evidence_aggregate_v1.md)은 단위 다중 상태·완전성·등록 근거가 있는 범위별 원인 수와 호환되는 후보별 시간을 집계한다. 결측·충돌·미판정이 있으면 총수/최초 시각을 확정하지 않으며, 입력이 보고한 주장의 집계가 원인 의미 인증을 대신하지 않는다. A안 실행기는 미구현이다.

| 보고할 결과 | 집계 조건과 제한 |
|---|---|
| 적용성 | 전체 모수 대비 탐색·준비 성공, 미지원·실패·미확인 이유. 수동 보완 성공과 자동 성공 분리 |
| entrypoint 실행 단위별 하나 이상 확인 | 주 요약 권고. 양쪽 같은 컴포넌트 확인·귀속 수준에서 판정하며 확인된 하한과 미판정 후보를 구분. 원인 수·종료정책을 대체하지 않음 |
| 컴포넌트 확인 고유 원인 | 실행 연결, 입력 전제, 고정 원본 제약 전체, 사전 속성 위반, 원인 귀속을 검토. 위치 일치만으로 포함하지 않음 |
| entrypoint TCCT 확인·컴포넌트 원인 미귀속 | 고정 entrypoint 제약 전체와 정상 계산/관찰 관계·역할을 확인한 별도 결과. 단위/후보 수·시간·귀속 실패 이유를 보고하고 컴포넌트 확인 원인 수에 섞지 않음 |
| 검토·투영·귀속 미판정 | 방식별 수·분모·사유·비용과 같은 수준 집계에 대한 영향. TCCT 층과 중첩 여부를 표시하고 미귀속 결과를 원인 수로 환산하지 않음 |
| 프로젝트 확인 고유 원인 | 별도 근거로 사전 정의한 프로젝트 의미 속성 위반까지 확인. 컴포넌트·entrypoint TCCT 확인 수와 합산하지 않음 |
| 맥락 후보 분류 | 특정 후보의 배제·미판정·양립 가능을 구분. 미판정을 오탐이나 진짜 결함으로 계산하지 않음 |
| 발견시간 | 사후 검토를 통과한 실행의 후보 생성시각 또는 기록된 완료시각 상한. 사람의 검토 완료시간과 구분 |
| 비용 | 준비·실행·맥락 판정·수동 검토·총비용. 캐시 조건과 메모리/자원 제한 명시 |

각 방식에 동일한 검토 기준을 적용한다. 주 성과의 양성 사례는 모두 그 기준으로 검토한다. 추가 경고를 표본 검토할 경우 추출 규칙·분모·미판정률을 밝히며, 검토된 일부의 정밀도를 전체 정밀도라고 부르지 않는다.

주 비교는 사전 일반 TCCT 기준의 컴포넌트 확인·원인 귀속을 권고하며 계약/프로젝트 의미 속성은 보조층으로 나눈다. 동일 수준의 확인 여부·최초 확인 대상 시간·고유 원인 수를 함께 보고한다. 원인 수는 종료·배분을 포함한 파이프라인 수율로 비교할 수 있으나 순수 oracle 능력의 우위는 아니다. 알려진/추가 원인에는 양쪽 대칭 규칙을 적용하고 사후 새 명세는 탐색층으로 분리한다. timestamp와 하네스 시각 연결이 검증되지 않으면 연결된 run 완료시각 상한을 쓰며, 확인 후보가 없으면 시간은 미관측이다. 선행 후보의 검토가 불완전하면 최초라고 확정하지 않는다. 미판정을 음성으로 치환하거나 entrypoint 증거를 컴포넌트 원인 수에 더하지 않는다. 세부 권고는 [결정용 기록 §3](scope_decision_final_2026-10-01.md#3-비교-수준지표종료-정책)에 있다.

[지표별 K5·K7](scope_decision_final_2026-10-01.md#6-지표별-기여-판단과-중단-기준)에 따라 손실 단위가 구제 단위 이상이면 해당 이진 지표의 관측 순증가가 없다는 뜻이다. 발견시간·고유 원인 수·비용을 포함한 RQ1 전체의 이득을 부정하지 않는다. 미판정 영향은 같은 수준에서만 분석하며 타당한 범위를 정할 수 없으면 해당 지표의 확고한 우위 주장을 보류한다.

컴포넌트 확인 여부와 맥락 판정은 별도 축이다. 같은 컴포넌트 원인이 여러 호출 위치에서 관측돼도 고유 원인 수를 늘리지 않는다. 특정 후보가 모든 관련 호출 위치에서 배제됐다는 사실은 그 컴포넌트의 다른 후보까지 배제하지 않는다.

## 5. 맥락 후보배제 평가의 최소 요구

- 지원하는 판정 범위·가정·신호 대응·분석 실패 처리와 근거 출처를 명시한다.
- 정상 실행 관찰이나 보장되지 않은 입력 태그를 실제 회로가 강제하는 조건으로 대체하지 않는다.
- 결과를 얻지 못하면 미판정으로 보존한다. 전체 제약과 양립한다는 사실만으로 최상위 속성 위반을 확정하지 않는다.
- 기존에 검토된 개발 자료와 적절한 통제 자료로, 배제의 정확성·알려진 유효 결과의 유지·미판정률·처리 비용을 점검한다. 평가용 자료에 맞춰 규칙을 조정하지 않는다.
- 사후 배제는 보고의 신뢰성에 관한 결과다. 첫 후보에서 종료된 탐색의 기회를 복구했다거나 탐지율을 높였다는 주장에는 별도 증거가 필요하다.
- 초기 배제는 특정 후보의 경계값에 한정한다. 원인 전체 배제나 경고 삭제로 해석하지 않고, 전제 위반·abort형·검사 종류·미판정·호출 위치 범위를 별도로 보존한다. [초안 §5의 증거 의무](scope_decision_2026-10-01.md#5-특정-후보-배제-입력-전제와-abort형)는 유지하되 현재 단계 순서는 [결정용 기록 §4](scope_decision_final_2026-10-01.md#4-n4-단계와-제안-상한)를 따른다. 비교 가능성과 대응 검증을 먼저 확인하며, 단순 정상 관찰이나 미검증 투영값을 양립 통제로 쓰지 않는다.
- 새로운 범용 solver, 전체 명세 자동 추론, 임의의 회로에 대한 완전성을 이번 목표에 넣지 않는다.

## 6. 고정 전 점검

N5에서 **초기 대상 목록**·노출층·포함/제외·단위 생성·중복 제거·예산·준비 실패/미지원/재시도 처리, 대표 순서·seed·자원·검토·분석 규칙과 도구/자료 해시를 먼저 고정한다. 로컬 버전 문서·대상 목록·파일/도구 해시·날짜·miiz 결정 기록으로 남기며 새 git commit은 요구하지 않는다. 미해결 설계를 빈칸인 채 고정됐다고 선언하지 않는다.

[현재 N5 고정안](scope_decision_final_2026-10-01.md#5-n5-고정-방식과-평가층)에는 종료/잔여 예산·재시작, 반복 집계, 양쪽 하네스 동등성, 검토 순서·상한·표본·원인 귀속·수준 변환 실패, 시간 관측 종료, 계열 군집도 포함한다. SoK의 실제 실행 제한은 미해결이며 우리 예산과 분리해 한계로 남긴다.

새 캠페인의 준비는 고정된 초기 목록과 규칙을 따라 N6에서 수행하도록 설계한다. 실제 단위·설정·호출 위치·신호 대응·컴파일 산출물·준비 manifest는 이후 생성 가능하되 해당 실행 전에 해시·성공/실패/미지원/보류 이력을 남긴다. 준비 성공 사례만 사후 선정하지 않는다. 과거 T2b 등의 준비는 지우지 않고 별도 노출·준비층으로 보존한다. 이번 N4-1은 [채택 기록 §3](scope_decision_accepted_2026-10-01.md#3-이번-n4-1-구현과-검증-범위)와 후속 메타데이터 집계 지시에 한정하며 새 평가 준비나 후보 생성 실행을 포함하지 않는다.

평가 후보에 zkFuzz를 실행하기 전에 프로토콜을 고정한다. 실패한 결과를 버리거나 성공할 때까지 바꿔 실행하지 않는다. 환경 장애 처리와 허용된 반복은 사전에 규정하고 모든 시도를 남긴다. 결과를 본 뒤 방법을 바꾸면 기존 자료를 보존하고 후속 결과의 개발/탐색 성격을 분명히 한다.

고정 프로토콜·manifest·계약·실행 기록·검토 판정은 수정하지 않는다. 원시 자료와 컴파일 산출물은 ignored `runs/`에 두고 공유 문서는 값 없는 경로·해시·판정·시간을 사용한다.
