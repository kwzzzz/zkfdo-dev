# N3 최종 결정용 기록 (2026-10-01)

**상태: 문서 정리 완료·miiz 최종 확인 대기. N4 미착수, N5 프로토콜 미고정.** 제목의 ‘최종’은 결정용 기록을 뜻하며 승인 완료가 아니다. 아래 채택·수정은 이 정리안에 반영한 분류다. miiz가 선택할 항목은 **§7 한곳**에 모았다. 시간 상한의 채택과 실제 개발·실행 허가는 별개다.

근거인 [N3 초안](scope_decision_2026-10-01.md)과 [독립 검토](../reports/n3-scope-review-2026-10-01/REVIEW.md)는 그대로 보존한다. 이 기록은 독립 검토의 F1–F6·K1–K7과 사용자 보정을 반영해 초안의 해당 권고를 대체한다. [N1 감사](../reports/sok-artifact-audit-2026-10-01/REPORT.md), [N2 검토](../reports/methodology-review-2026-10-01/REVIEW.md), 과거 고정 자료·준비·실행·판정도 변경하지 않는다.

**주 기여 가설은 자동 분해 시스템, 랭킹은 보조 가설, 맥락 후보배제는 신뢰성 과제다.** 랭킹 폐기나 맥락 오탐 제거 중심 전환을 결정하지 않는다. 기술적 차별성·개발과 분리된 평가 성과·신뢰성·총비용으로 기여를 평가하며, 주장 축소와 방향 전환을 구분한다.

## 2. 기술적 기여와 현재 입증 범위

| 기술 문제·해결 가설 | 현재 근거 | 추가 입증 의무 |
|---|---|---|

독립 검토 F1·F4의 **첫 분기 컴포넌트로의 투영은 후보 검토 방법의 가설**이다. 정상 계산과 후보의 신호 대응, 경계값, 원본 제약 전체, 속성 위반 및 원인 연결을 검증한 범위만 인정한다. 첫 차이가 곧 유일 원인이라는 보장은 없으며, 다중 원인·최적화·root·abort형에서 투영이 성립하지 않으면 미판정이다. 변이 위치가 JSON에 없다는 사실만으로 특정 투영 방법의 충분성·필수성이 입증되지는 않는다.

원본 템플릿을 호출하는 wrapper 구성 사실과 **원본 의미 보존의 검증**도 구분한다. 의존성·파라미터·입출력·컴파일 설정과 제약/신호 대응이 확인된 범위의 관계만 주장하며, caller 제약 보존이나 임의 회로의 의미 동등성을 선언하지 않는다. 첫 분기 투영, 통째 후보 귀속, wrapper 의미 보존, 후보 timestamp 복원은 현재 성과 문장에 넣지 않는다. 이번에는 기존 문서만 대조했으며 검토 보고서의 정적 관찰을 새 실행 검증으로 승격하지 않았다.

## 3. 비교 수준·지표·종료 정책

주 비교 권고는 **사전 정의한 일반 TCCT 기준의 컴포넌트 확인과 원인 귀속**이다. 입력 전제·고정 원본 제약 전체·정상 계산과의 관계·검사 종류를 함께 기록한다. 별도 계약/프로젝트 의미 속성은 조건부 보조층으로 분리한다. 알려진 원인과 추가 원인 모두 양쪽 방식에 같은 기준·귀속 절차·검토 상한을 적용하며, 사후 새 명세가 필요한 결과는 양쪽 모두 탐색층이다([초안 §4·5](scope_decision_2026-10-01.md#4-동일-검토-수준-성과-지표와-종료-정책)).

| 결과층 | 집계 권고 | 미판정의 영향 |
|---|---|---|
| 컴포넌트 확인·원인 귀속 완료 | 실행 단위별 하나 이상 확인, 최초 확인 대상 시간, 검토된 고유 원인 수를 함께 보고 | 원인 중복 여부가 불명확하면 확정 고유 수에 추가하지 않고 미귀속군으로 보존 |
| entrypoint TCCT 확인·컴포넌트 원인 미귀속 | 별도 확인 단위/후보 수, 검토 범위·시간·귀속 실패 이유 보고. 컴포넌트 고유 원인 수에 혼합하지 않음 | entrypoint 증거를 버리지 않되 컴포넌트 원인 하나로 환산하지 않음. 프로젝트 의미 속성 확인과도 별개 |
| 검토/투영/귀속 미완료 | 방식별 수·분모·사유·검토 비용과 확인된 하한 보고. 위 TCCT 층과 중첩 여부를 연결키로 표시 | 확인 0과 완결된 음성을 구분. 같은 수준에서 논리적으로 가능한 범위만 민감도 분석하며 미판정 후보 수를 원인 수 상한으로 가정하지 않음 |

주 양성은 전수 검토한다. 시간순 검토의 앞부분이 완결되지 않으면 ‘최초’가 아니라 **현재 확인된 후보 시각과 미검토 선행 후보**를 보고한다. 후보 시각의 의미와 하네스 시각 연결이 검증되지 않으면 연결된 run 완료시각 상한을 사용한다. 확인 후보 없음은 시간 0이 아니며, 조기 종료·예산 종료·준비 실패·검토 중단을 구별한다. 검토 시각·비용은 생성 시각과 따로 둔다. 이진 지표만으로 첫 미확인 후보 종료의 기회 손실이 없어지지 않는다.

**연구 설계 권고 A:** 결과 종류·사후 판정에 의존하지 않는, 실행 단위 공통 총할당 내 반복 시도·잔여 예산 정책. 조각마다 전체 예산을 복제하지 않고 호출/재시작 비용·중복 반환·환경 장애·seed 규칙을 사전 정의한다. **대안 B:** 통째 한 호출·조각별 한 호출의 native-stop 조건을 명시한 파이프라인 비교. B는 허용 가능한 제한적 설계지만 총예산을 사용한 탐색이나 실제 사용 자원의 동등성을 뜻하지 않는다. 기존 기능이 A를 지원하지 않는다고 B로 자동 전환하지 않는다.

A의 스케줄링·종료·로그·예산 집계 구현과 양쪽 검증은 **필요사항이지 완료 사실이나 이번 작업 허가가 아니다**. 독립 검토 §1의 고정 사본은 프로세스당 최대 한 후보를 반환한다고 보고한다. 캠페인의 반환 수는 하네스 정책에 달려 있다. 어느 정책이든 할당을 소진했다는 사실만으로 사용 CPU·벽시계·메모리·대기 시간이 같아지지 않는다. 같은 자원 상한과 실제 사용량을 따로 보고하며, 공정성의 범위도 그 측정에 맞춘다.

맥락 판정은 특정 후보의 특정 호출 위치 경계값 배제로 제한한다. 관련 위치가 모두 확인·배제되지 않으면 entrypoint 전체 배제는 미판정이며 원인 전체 배제·경고 삭제로 바꾸지 않는다. 입력 전제 위반은 계약 조건부 부적격이지 무조건 오탐이 아니다. 출력 차이형과 계산 abort형을 나누고, abort를 입력 모호성과 동일시하지 않는다. 대응 실패·지원 밖·시간 초과는 unknown, 호출자가 없는 root 맥락 배제는 N/A다. 상세 증거 의무는 [초안 §5](scope_decision_2026-10-01.md#5-특정-후보-배제-입력-전제와-abort형)를 유지한다.

## 4. N4 단계와 제안 상한

**미착수다.** 아래는 기존 개발 자료에서 수행할 작업의 설계이며 소스 열람·코드 변경·새 실행을 승인하지 않는다. 초기 범위는 초안의 기존 inference·zk-email 최대 2개 프로젝트와 기존 v1–v3 검토 증거다. 통째 후보가 필요한 경우에도 새 개발 실행의 대상·종류·범위는 후속 착수 기록이 있어야 한다. 부족한 증거를 자동으로 생성하거나 새 평가 후보를 열지 않는다.

| 순서 | 최소 범위 | 제안 상한 | 완료·중단 기준 |
|---|---|---:|---|
| 1. 비교 가능성 | 양쪽 하네스·시간·종료·자원·증거 연결, 선택 정책의 동작, 양쪽 후보의 같은 수준 검토 및 별도 entrypoint 확인 경로 | 12시간 | 양쪽 최소 한 예시와 검증 범위가 기록돼야 통과. 통째 후보 부재·투영/귀속 실패·상한 도달이면 중단하고 K1 적용 여부 재판단. 기록만 있다고 검증 통과로 세지 않음 |
| 2. 준비 병목 한 종류 | 외부 의존성 식별·버전 고정과 타깃/실패 사유 연결 | 10시간 | 기존 개발 entrypoint의 자동 준비 개선을 확인. 범용 함수·배열 해석이나 전면 호환이 필요하면 미지원으로 종료 |
| 3. 맥락 판정 탐침 | 검증된 대응 위의 직접 호출자 제약 관계 한 종류 | 10시간 | 전체 고정 제약 및 대응으로 실제 양립을 입증한 통제 값을 잘못 배제하지 않아야 함. 정상 계산 관찰·통째 후보 투영만으로 양립 통제를 선언하지 않음. 오배제/대응 실패면 자동 배제 중단 |
| 4. N5 기록 | 대칭 검토·순서·상한·비용·미판정·준비 manifest 형식 | 8시간 | 제3자가 추적 가능한 기록 형식과 미해결 목록. 미해결 설계를 고정 완료로 바꾸지 않음 |

총 **40 담당자 작업시간** 및 각 단계 시간은 추정치·기한·승인 예산이 아닌 제안 상한이다. 단계 1을 준비·맥락 작업보다 먼저 수행한다. 단계 1 뒤 관문을 통과하거나 비교 주장 축소를 명시적으로 기록한 뒤에만 후속 범위를 정한다. 단계 3은 대응 검증 없이는 진행하지 않는다. 남은 시간으로 범위를 늘리지 않으며 상한 안의 실패도 결과로 남긴다. 신규 재시작 구현이 필요하면 같은 상한 내 가능성과 별도 작업 범위를 먼저 판단한다.

## 5. N5 고정 방식과 평가층

전체 **70 사례 / original 선언 56 사례 / 지원 부분집합**의 관계, 사례 수·실행 단위 수·고유 원인 수의 구분은 유지한다. original 부재 14건, 준비 실패·미지원·unknown을 보존한다. **36개 잠재 묶음은 확정 실행 단위가 아니다.** 단위는 프로젝트·재현 가능한 소스 버전·entrypoint·실행을 바꾸는 설정으로 생성하며, 라벨·검토 predicate·반복·방식 차이만으로 새 단위 예산을 주지 않는다. family는 독립성 군집이고 실행 중복 키와 다르다. production/test/unknown, root/child 및 불완전 탐색을 별도 기록하며 root를 일괄 제외하지 않는다([초안 §1–3](scope_decision_2026-10-01.md#1-전체-모수와-지원-가능한-부분집합)).

노출은 개발 사용·실행·준비/컴파일·소스/패치 열람·프로젝트 opened·메타데이터·공개 결과 지식을 구분한다. **D(개발)**는 방법·규칙·선정 조정에 사용한 자료와 확인된 개발 계열, **S(개발과 분리)**는 그 사용이 없다는 이력 근거를 갖춘 층, **Q(불명)**는 사용·계열 관계를 확인 못 한 층이다. 목록 미등재만으로 S에 넣지 않는다. 기존 5건·3repo는 미노출로 복원하지 않으며, 70건의 공개 결과 지식 때문에 S도 never-exposed를 뜻하지 않는다. 과거 T2b 등의 준비·소스 이력은 별도 열/층으로 보존하고 층별 결과와 영향 분석에 반영한다. 새 고정이 과거 준비 이전부터의 독립성을 만들지는 않는다.

고정은 **로컬 버전 문서·대상 목록·도구 및 파일 해시·날짜와 miiz 결정 기록**으로 남긴다. 새 git commit은 필수가 아니며 이번에 commit하지 않는다. 대상의 기존 commit ID는 소스 식별 정보로 사용할 수 있고, 없으면 아카이브/트리·파일 해시 등 재현 가능한 식별자를 쓴다. 이후 준비 manifest가 해당 고정본을 참조하게 하며 고정본·과거 준비 이력은 덮어쓰지 않는다. 이 절은 **새 캠페인의 고정→준비→평가** 순서이지 과거 준비가 없었다는 선언이 아니다. 방법을 다시 조정하면 새 버전과 개발/탐색층으로 기록한다.

N5의 수치·규칙은 아직 미정이다. SoK 논문/README 600초·JSON 300초·builder 600초의 **실제 실행 제한도 미해결**로 둔다. 이를 우리 예산이나 동일 환경 기준선으로 자동 상속하지 않는다. 이번 문서 작업에는 준비 산출물 생성이나 실행이 포함되지 않는다.

## 6. 지표별 기여 판단과 중단 기준

| 관문 | 권고 판단 |
