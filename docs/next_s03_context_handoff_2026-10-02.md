## 현재 결정: 원인 귀속과 중복

S-04에서 원본 `main.out`은 제약 46개 중 어디에도 나타나지 않고, 같은 입력의 정직한 witness와 다른 wire는 `main.out` 하나뿐이다. 이는 원본 `out <-- quot`가 출력 차이를 허용한다는 강한 구조 증거다. 그러나 사전 S-04 규칙은 실제 수정본의 다른 조건도 통과하고 같은 입력의 수정본 정직한 계산이 성공해야 단일 원인에 귀속한다. 후보의 정직한 `quot` 자체가 40비트 밖이라 실제 수정본은 범위 검사에서 중단됐다. **S-04 판정은 미귀속으로 보존한다.** 구조 관측만으로 소급 등록하거나 31건 중 새 고유 원인 하나로 세지 않는다.

N5에서 사용할 전향적 후보 규칙은 개발 중 별도 통제로 시험한다. 원본의 `out <-- quot`만 `out <== quot`로 바꾸는 **출력 제약만의 최소 수리**, 범위 검사만 더하는 수리, 실제 수정본을 구별한다. 같은 후보 입력에서 출력 제약만의 수리가 후보의 다른 출력은 거부하고 정직한 출력은 받아들이는지, 범위 수리는 후보와 정직한 계산을 모두 입력 영역 밖으로 배제하는지 분리한다. 범위 안의 사전 고정 대조 입력도 사용한다. 컴파일 최적화로 wire가 재번호화·합쳐질 수 있으므로 원본 `.wtns`를 수정본에 그대로 대입하지 않는다. 이 후속 진단은 **사후 개발 분석**이며 S-04의 사전 판정이나 N5를 소급 변경하지 않는다. 최소 수리의 출처·diff·도구 hash와 성공/중단 기준을 새 SCOPE에 고정한 뒤 수행할 수 있다.

원인 등록 키는 원본 프로젝트 계보·정의된 template의 소스 지점·깨진 제약 관계·독립 최소 수리로 정하는 방향이다. 반복 seed, `IntDiv(40/80/120)` 파라미터, 같은 지점을 담은 부모 조각과 호출 위치는 그 지점의 한 원인으로 병합한다. `Subtract`의 내부 승수 무제약과 `IntDiv`의 출력 무제약은 소스 지점과 수리 관계가 다르지만 같은 fix PR/zkbugs 대표 항목에 속한다. 향후 둘 다 귀속되더라도 독립 프로젝트 2개나 독립 PR 2개로 말하지 않고 **site 원인**과 **PR/결함 클러스터**를 분리한다. 최종 등록·대칭 집계는 N5에서 고정한다.

## 다음 병렬 작업

### S-05: S-03 첫 occurrence의 실제 의미 검토

S-03 원본은 메타데이터 검산 부분 완료로 보존한다. S-05는 같은 A-02 attempt 1 `Subtract()` 후보(SHA-256 `dae6e8b397f2b25269f9711443449b73ba6ba86f4ca7a4397cf318fbfc143258`) **한 건만** 새 버전의 SCOPE/REPORT로 검토한다. 새 SCOPE는 S-03 SCOPE·REPORT·31건 인벤토리, A-02 ledger/evidence, 후보·원본·wrapper·도구 해시, 입력 전제, R1CS 전체 만족·정직한 witness 대비 출력/abort, 귀속·중복·호출 맥락·중단 기준을 후보 값 확인 전에 고정한다. S-01의 과거 `Subtract` 판정을 복사하지 않는다.

원본 제약은 Python 평가와 snarkjs처럼 독립된 두 방법으로 검증하고, 같은 입력으로 정직한 witness를 다시 계산한다. 차이가 있으면 첫 차이와 실제 수리 근거를 확인해 S-01 원인과 같은지 판정한다. `Subtract()`는 여러 호출 위치에서 쓰이므로 template 이름으로 callsite를 단정하지 않는다. 가능한 호출 위치 각각의 입력 대응·도달성을 확인하고 원본 entrypoint에 투영해 실제 전체 witness/TCCT를 검증할 수 있을 때만 entrypoint 결론을 쓴다. 투영 불가·자료 결측은 별도 미판정이다. S-05의 컴포넌트 판정이 확인되거나 명시적 비해당으로 끝나면, 앞선 모든 candidate occurrence의 검토가 완료됐는지와 시간 의미를 확인한 뒤에야 최초 확인 대상 시간을 계산한다. parent 로그 관측 offset은 정확한 생성시각이 아니다.

### C-01: 값 없는 호출 위치·정상 경계 대응

후보 값을 읽지 않고 A-02 `Subtract()`와 `IntDiv(40)` 정의가 production entrypoint의 어느 호출 위치에 인스턴스화되는지 원본 소스·plan·`.sym`·기존 정상 witness에서 조사한다. 모든 가능한 callsite와 중첩 경로를 열거하고 template 정의/파라미터/호출 위치/원본 신호 경로의 구분키를 기록한다. 서로 같은 컴파일 산출물을 공유하는 위치라도 각각의 정상 입력·출력 대응을 확인한다. 이미 완료한 NB-01의 정상 경계 연결을 재사용할 수 있으나, 정상 witness의 일치가 반례의 도달성이나 후보 투영을 입증하지는 않는다. 검증 가능한 범위의 일반 mapping 절차와 회귀를 구현하고, 모호하거나 최적화 때문에 신호가 사라진 위치는 명시적 unknown으로 남긴다. 이 작업은 특정 후보 재현·결함 판정·새 퍼징이 아니다.

각 작업은 자신의 새 범위·결과와 계획 행만 수정한다. 원시 후보·witness·컴파일 산출물은 ignored `runs/`에 둔다. 공유 파일에는 값 없는 경로·해시·판정·비용만 남긴다. 코드 변경 시 AGENTS.md의 fmt·clippy·cargo test를 실행한다. 완료 후 N4-1과 N5를 자동 완료하지 않고 commit/push/PR은 하지 않는다.
