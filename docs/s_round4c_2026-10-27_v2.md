## 다시 확인

저장소 루트에서 아래는 검사/순서 출력만 한다. 이미 존재하는 결과 파일은 덮어쓰지 않으므로 재실행마다 새 label/경로를 쓴다.

```sh
nice -n 19 python3 -B scripts/s_round4c_monitor_20261027.py --label 4c-tests-recheck-001 --timeout 120 -- python3 -B scripts/s_round4c_test_20261027.py -v
nice -n 19 python3 -B scripts/s_round4c_monitor_20261027.py --label 4c-recount-recheck-001 --timeout 120 -- python3 -B scripts/s_round4c_protocol_20261027.py --recount --output runs/s-round4-2026-10-27/round4c/guarantees-recheck-001.json
nice -n 19 python3 -B scripts/s_round4c_sequence_20261027.py sequence --output runs/s-round4-2026-10-27/round4c/order-recheck-001.json
```

마감 뒤 CLI는 `plan-w --input … --input-sha256 … --output …`, `run-w --input … --input-sha256 … --resources … --resources-sha256 … --output … --execute`, `conclude --input … --input-sha256 … --output …`다. 선택 계획은 `plan-w --all-15`, 실행은 추가로 `--optional-all-15-human-start --completed-required … --completed-required-sha256 …`가 필요하다. `…`는 아직 생성되지 않은 **검증된 입력과 그 SHA**이며 지금 실행할 명령으로 제시하지 않는다.

원래 4c 산출물의 경로·크기·SHA-256은 [new-files-sha256.json](../runs/s-round4-2026-10-27/round4c/new-files-sha256.json), 목록 자체의 해시는 같은 이름의 `.sha256`에 둔다. 기존 파일을 수정하지 않고 새 보고서·개정안·스크립트·출력만 추가했다.

이번 후속 버전과 결정 기록의 SHA-256은 [followup SHA 목록](../runs/s-round4-2026-10-27/round4c/followup-boundary-20261027/new-files-sha256.json)에 별도로 둔다. 원보고서와 원래 해시 목록은 보존했다.
