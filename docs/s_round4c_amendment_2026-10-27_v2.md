# S 4c 실행 순서 개정안 v2 — 2026-10-27

이 문서는 [기존 개정안](s_round4c_amendment_2026-10-27.md)의 **시작 조건, aq replay 표본, 새 J 중복 제외, aq 자료 보존**만 바꾸는 후속 추가조항이다. 기존 개정안과 사전 등록 기록은 수정하지 않는다. 아래에서 바꾸지 않은 표본·채택·S/J/W·자원·중단·결론 규칙은 기존 개정안을 따른다. 두 문서의 실제 SHA-256을 각각 확인하고 실행 계획에 결속한다. 이 문서는 실행 결과나 miiz의 실행 승인을 기록하지 않는다.

## 시작 조건과 aq 상태 사본

6번 실행 순서 스크립트는 고정 시각 `2026-10-28T15:00:00Z` 도달 여부 대신, **aq 실행기 프로세스가 없고 v3_2 state가 최종 상태임을 확인한 뒤** 시작한다. 실행기는 aq 프로세스를 종료하거나 재개하지 않는다. 최종 상태로 인정하는 경우는 다음 셋뿐이다.

1. `status=completed`이고 `finished_at`이 기록된 정상 완료.
2. `status=stopped`, `stop_kind=deadline`, `stopped_at`이 기록된 마감 종료.
3. `status=stopped`, `stop_kind=interrupted`, `stopped_at`이 기록되고 신호에 따른 정상 정지와 해당 요청의 저장이 확인된 경우. 단순히 `interrupted`라는 값만으로 통과시키지 않는다.

세 경우 모두 state의 요청 중 `running` 상태가 없어야 하며, 완료·실패로 기록된 요청의 저장된 결과·측정 기록과 SHA 결속을 확인한다. 검사 실패, 프로세스 검사 불가, 불완전한 요청은 시작 거부 사유다. **기존 마감 시각보다 전에 시작할 때는 `--aq-stopped-by-miiz`를 별도 명시 인자로 요구**한다. 그 인자는 실제 프로세스·state 검사를 대신하지 않는다. 마감 이후에는 이 인자를 필수로 요구하지 않는다.

프로세스 부재와 최종 state를 확인한 **스크립트 시작 시점에** 원본 `state-v3_2.json`의 바이트 사본을 새 4c 출력 아래에 만들고 원본 경로·사본 경로·SHA-256·복사 시각을 기록한다. 사본을 만든 뒤 원본이 바뀌거나 aq 프로세스가 다시 나타나면 시작을 멈춘다. 사본은 이후 replay 선택의 고정 입력이며, 실행 도중 갱신되는 aq state로 표본을 다시 고르지 않는다.

## Replay 표본과 새 J

Banyan 표본 규칙은 유지한다. aq 표본은 위 **시작 시점의 최종 state 사본**에 기록된 완료 요청에서 요청별 aq peak가 작은 순으로, 동률이면 요청 번호순으로 5개를 고른다. 여기서 peak는 해당 요청의 workspace 정리 영수증에 기록된 `du_bytes`의 최대값이다. 요청·입력·완료 결과·SHA 검사를 통과하지 못한 행은 같은 사본의 다음 적격 행으로 대체한다. 미완료 요청이나 실행 전 만들어 둔 다른 시점의 inventory를 표본의 근거로 쓰지 않는다. 선택된 5개의 state 사본 SHA와 요청·peak·순서를 기록한다.

새 J의 과거 SHA 중복 제외 집합에는 **이미 판정이 끝났음을 완료된 J 결과 및 후보 SHA 결속으로 확인한 과거 후보만** 넣는다. 과거 목록에 SHA가 있다는 사실만으로 제외하지 않는다. 과거 후보의 J 실행이 미시작·중단·실패했거나 완료 판정 기록이 없으면, 같은 SHA의 이번 S 후보도 새 J 요청에 넣는다. 이번 실행에서 새 J에 이미 넣은 SHA의 반복은 기존처럼 한 번만 처리한다. 각 제외·포함 판단의 근거가 된 과거 결과 경로와 SHA 또는 미판정 사유를 남긴다.

## aq 자료 보존과 재개

기존 **aq 판정 폴더, 요청 결과, workspace, cache, instance-store 및 state는 삭제하거나 옮기지 않는다.** 새 4c의 요청별 작업 폴더와 aq 자료의 경계를 확인한 뒤 기존 4c 전용 정리 규칙만 적용한다. 4c 실행을 위해 aq의 정리·이동·명령 변경을 요구하지 않는다. aq는 나중에 기존 v3_2의 **같은 명령과 재개 설정**으로 이어서 돌린다. 그때의 새 구간 시작 가능 여부는 aq 실행기의 기존 마감 규칙을 따른다. 4c replay와 새 J는 aq 원본의 재개 가능성을 훼손하지 않는다.
