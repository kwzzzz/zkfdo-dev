## 3. 이번 N4-1 구현과 검증 범위

- 기존 결과 형식과 검토 엔진의 연결을 정적으로 확인하고, 통째·분할 결과를 받는 공통 기록 경로를 최소 변경으로 구현한다.
- 실행 단위·방식·반복·자료 버전·할당·실제 사용 자원·종료 사유·후보 시간의 의미·증거 참조·검토 상태를 분리한다. 읽을 수 없는 기존 값은 `unknown`과 사유를 남기고, 원본 기록을 사후 수정하지 않는다.
- 컴포넌트 확인과 원인 귀속, entrypoint TCCT 확인과 원인 미귀속, 검토 미완료를 별도로 보존한다. 투영·귀속 실패를 음성이나 고유 원인 하나로 환산하지 않는다. 같은 원인의 중복과 연결 정보도 유지한다.
- A안의 예산·종료·잔여 예산 규칙을 **기록 형식**에 표현한다. 이번에는 반복 실행기나 새 후보 생성 기능을 구현·실행하지 않는다.
- 기존 값 없는 메타데이터와 비보안용 합성 fixture로 정상 연결·결측·중복·시간 의미 차이·귀속 실패·검토 중단을 점검한다. 실제 결함 재현 자료를 새로 만들지 않는다. 코드 변경 뒤 `cargo fmt`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test`를 수행한다.

병렬 검토 파일 `reports/n4-1-review-contract-2026-10-01/REVIEW.md`는 별도 소유자의 문서이며 수정하지 않는다. 도착하면 구현 관련 필수 의견을 확인해 이번 범위에서 가능한 수정을 반영하고, 충돌이나 범위 밖 요구는 근거와 함께 현재 작업 기록에 남긴다. 추가 계획 보고서만 작성하고 구현을 대신하지 않는다.

## 4. N4-1 관문과 남는 입증 의무

이번 기록 경로의 구조적 테스트 통과는 통째 후보의 의미 검증이나 N4-1 전체 관문 통과가 아니다. [채택한 관문](scope_decision_final_2026-10-01.md#4-n4-단계와-제안-상한)은 양쪽 후보의 같은 수준 검토·검증 범위, 투영·원인 귀속과 별도 entrypoint 확인, 하네스 시간·종료·실제 자원 및 선택 정책의 동작 근거를 요구한다. 첫 분기 투영·wrapper 의미 보존·후보 timestamp 복원도 미검증 범위를 현재 성과로 쓰지 않는다.

이번 허용 범위로 채울 수 없는 의미 검증과 A안 실행 정책의 구현·공정성 확인은 남은 조건으로 보고한다. 관문 미충족 시 N4는 진행 중으로 유지하고 N4-2를 시작하지 않는다. 후속 실행이 필요하면 대상·종류·범위를 별도로 남겨야 하며, 평가 프로토콜 고정 전 평가 후보 퍼징 금지는 유지한다.

구현 결과·검사 결과·관문 판단의 현재 상태는 [계획 진행 표](plan_revision_2026-10-01.md#7-진행-표)와 [START_HERE](../reports/START_HERE.md)에 기록한다. 이 결정 문서는 허용 범위와 채택 근거를 보존하며 commit/push/PR은 수행하지 않는다.
