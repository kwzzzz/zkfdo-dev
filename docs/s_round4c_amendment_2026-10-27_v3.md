표본은 **v2.2**의 완료 요청만 사용한다. Banyan 수정 S 24개 전체, 취약 S 최대 108개를 요청 순서로 선택하되 취약 표본 기록시간 합이 3시간을 넘기 직전에서 멈춘다. 입력·SHA 미검증 행은 다음 적격 행으로 대체하며, 단순 자료 부족을 시간 한도에 도달한 것으로 취급하지 않는다. aq는 시작 시점 최종 state의 요청별 실측 workspace peak 오름차순 5개다. v3.2 state가 없을 때만 v3.1을 쓴다. RQ-C·결함 위치는 이 선택에 사용하지 않는다.

시작 조건은 aq 프로세스 부재와 저장된 최종 상태다. 마감 이전에는 `--aq-stopped-by-miiz`가 추가로 필요하다. 정상 완료·마감 종료·`signal 2/15; request saved` 정지를 허용하고 저장 중 요청은 거부한다. 실행 중 aq가 다시 나타나거나 state SHA가 바뀌면 이번 자식 작업만 중단한다. aq 폴더·캐시·재개 상태는 변경하지 않는다.

순서: 사전 검사 → 격리된 J cargo 검사 24개 → replay → Banyan view 비교 → S → 새 J → 엄격층 채점·비용 합산 → 새 L1 리비전의 같은 총시간 W → W 후보 확인·결론. 모든 replay와 view 표본에서 **판정 종류와 사유가 같아야** 한다. 하나라도 다르면 평가에 v2.3을 채택하지 않고 멈춘다. 승인된 이 문서의 실제 SHA를 실행 인자로 받고 S·새 J 직전에 다시 확인한다.

24개 테스트의 판정·assert는 보존한다. 새 격리 crate에서 원래 fixture 경로, v2.3 CLI 호출, 임시 폴더, `j-v2.3` 저장소 하위 경로만 바꾼다. 기존 테스트 한 개가 동결 폴더에 쓰는 경로는 새 이미지 임시 폴더로 바꾼다. `lift-instances`는 같은 라이브러리의 집계 전용 보조 명령을 사용한다. 새 엔진·도구·테스트 사본·원본 소스의 SHA를 확인한다. 테스트 빌드와 실행은 각각 기록하며 빌드 성공을 24개 판정 테스트 통과로 대신하지 않는다.

S 범위는 고정 A-Q 15리비전 × seed `2026100601/02/03`, seed당 600초·시도당 30초·메모리 10 GiB다. 정책 B SHA는 `edfc21d7c82353ce01a0b1a83958a7f885cd55ec4e5cb83815cc45f138319076`이다. 새 태그 래퍼·view·원 fragment·소스 SHA와 새 준비 묶음을 고정한다. 누락·준비 실패를 조용히 빼지 않는다. 원본 적격 래퍼를 복사·재정렬한 기존 묶음만으로 개선 준비가 완료됐다고 선언하지 않는다.

새 J는 실제 새 ledger의 후보를 읽는다. 과거 SHA만 존재하면 제외하지 않으며, 완료된 판정·후보 SHA가 결속된 경우에만 재사용한다. 엄격층에 재사용할 때는 원 요청·리비전·entrypoint·기준 입력의 결속도 확인한다. 미판정 과거 후보와 같은 SHA는 판정한다. 구성 입력과 미검증 입력은 공식 기준 입력 SHA와 구분하고 엄격층 효용 결론에 넣지 않는다. 공식 765건 재채점 회귀 검사를 유지한다.

J의 workspace·cache·instance-store는 `/Volumes/zkfdo-jcache/s-round4c-20261027/<이번실행>/` 아래 새 요청별 폴더다. 소스 루트 안에 J 출력을 두지 않는다. 요청 종료마다 aq v3.2가 쓰는 정리 모듈을 그대로 호출하고 증거는 join·채점에 필요하므로 보존한다. 보존한 실제 `du_bytes`는 다음 요청의 `ceil(1.2×max(60 GiB, 기록 peak))+보존분` 이미지 관문에 누적한다. 기존 aq 자료는 정리 대상이 아니다.
