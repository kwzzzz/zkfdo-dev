# 전체 비용 계측 운영 시범 v3: 판정 관문 정정

2026-10-28. [v1](n7_allcost_pilot_protocol_v1_2026-10-28.md)과 [v2](n7_allcost_pilot_protocol_v2_2026-10-28.md)의 시간·도구·회로·seed·군 순서·2회 시도 상한은 유지한다. **v5 실행 결과를 본 뒤 정정한 운영 관문**이므로 v5를 사후 통과로 재판정하지 않는다. 새 코드 SHA와 이 문서를 pin한 plan-v6을 새 출력에서만 실행한다.

v2의 “12군 모두 자연 후보 처리”는 음성 fixture의 전체 회로 W에 맞지 않았다. 그 회로에서 자식 출력은 최상위 출력에 닿지 않으므로 W가 후보 0개를 내는 실행도 정상적인 관찰이다. v5에서 이 경우가 3/3 발생했고, 기존 실행기의 `completed`는 후보·J 판정이 비어도 생성됐다. **v2의 전체 의미 관문은 미통과**로 보존한다.

v3 관문은 12군 각각에서 감독 완료·후손 정리, O0 제약 1~1,000, 원본 기준 증인 snarkjs 통과, 캠페인 기록 완결, fsync된 J 근거와 파생 색인의 일치를 확인한다. 양성 W/S 각 3군은 자연 후보 최소 1개와 예산 안 J의 원본 검증 L1 최소 1개가 필요하다. 음성 S 3군은 자연 후보 최소 1개와 예산 안 J의 `outputs_equal`·L1 0이 필요하다. 음성 W 3군은 자연 후보 0개를 허용한다. 후보가 있으면 J 판정을 확인하고, 미판정은 0건의 안전 증거로 세지 않는다. 시간이 끝난 군도 이미 fsync된 예산 안 근거는 인정하되, 결과가 불완전한 군은 실패 사유를 남긴다.

이 시범은 실행·계측 경로의 검사다. 음성 W의 후보 0과 양성 수율·시간을 방법의 성능 우위로 비교하지 않는다. v4의 14번째 시도 `PermissionError` 원인은 여전히 미확인이고, 2회 시도 통과는 긴 캠페인 안정성을 입증하지 않는다. 큰 A를 실행하려면 별도 반복 안정성 진단과 총시간·유휴 예산·원인 중복 제거 계획이 필요하다.
