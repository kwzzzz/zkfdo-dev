## 논쟁 후 결정

1. 옛 v3의 A-Q W 3회 중단을 현재 기록으로 읽은 해석을 철회했다. 뒤의 v4/v4.1 W는 **45/45 완료**됐다. W 자원 결손은 실행 부재가 아니라 새 동일총시간 W를 위한 *디스크 peak·보존량 영수증 0/45*다. 4d의 시작 검사 8결손은 남지만 이 45쌍의 원래 N5 퍼징을 다시 돌릴 이유는 아니다.
2. 외부 검토와의 논쟁에서 `W wall time을 S+J 총예산으로 쓰기`, boost `aligned`를 N5 필수 L1에 추가하기, S/W 후보의 구조 키 차이를 양성 가능성의 상한으로 쓰기를 철회했다. 앞의 두 개는 고정 규칙을 바꾸고, 마지막은 witness가 달라 성립하지 않는다.
3. **다음 개발 우선순위는 13리비전의 기준 입력 출처 복구**다. N5의 [2026-10-10 보충](n5_evaluation_protocol_v1_2026-10-06.md#a-맥락-판정j-기준-입력-보충2026-10-10-리드-판단-j-실행-전)은 원본 테스트·입력 도구를 그대로 실행해 입력 객체를 캡처하고 사람이 입력을 만들거나 고치지 않도록 한다. 따라서 커밋 JSON 키 수동 변경이나 테스트 문자열 정적 재구성은 엄격층 해법이 아니다. 현 로컬 파일과 설치 금지 조건에서 엄격 복구가 확정된 리비전은 **0/13**이다.

원본 도구가 정상 실행할 수 있는 **기존 로컬 자산**이 확인되면 리비전 번호순으로 입력을 캡처하고 정직 witness, 전체 O0 R1CS의 Rust 검사, snarkjs 검사를 통과시켜야 한다. 값과 후보로 입력을 맞추지 않는다. N5 §(d)는 네트워크 설치가 필요한 경우 실패로 기록하므로, 나중에 의존성을 설치해 얻은 입력을 기존 엄격 결과로 소급하지 않는다. 그런 후속은 별도 탐색층이다. 통과한 리비전에서만 기존 고정 후보에 J를 적용하며, 원래 결과 파일 대신 새 버전 기록에 남긴다. 원본 입력 출처를 확보하지 못한 리비전은 계속 `unavailable`이다. [후속 점검](rq1_inference_evidence_2026-10-28.md)에서 현재 로컬 경로 추가 복구 0/13을 확인했다.

4d는 별개의 추가 탐색층이다. [현재 8개 시작 결손](../runs/s-round4-2026-10-27/round4d/launch-v5/readiness.json)에는 Banyan 132건의 상세 입력, S의 21개 크기 미상 컴파일·6개 검사 미완료, J/W 결속·자원 영수증이 포함된다. 21개는 100,000제약 이하인지 아직 확인되지 않아 현 개정안의 새 컴파일 조건과 순환한다. 또 4d의 필수 W는 새 S L1 리비전에서만 실행되므로 N5의 15리비전 전체 K5a·비용 결론으로 넓힐 수 없다. 이 자료는 미승인 4d 실행을 시작할 근거가 아니다.

**확인한 것:** 45개 W 명세 SHA, 완료된 기존 45쌍, 13리비전의 W=0/S=261/엄격 J 준비 실패=261, 원본 입력 도구의 실패 유형, N5의 변경 금지 범위. 이번에는 퍼징·J·컴파일·설치를 하지 않았다.
