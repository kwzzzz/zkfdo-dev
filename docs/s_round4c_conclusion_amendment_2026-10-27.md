## 결론 기준

대상은 동결 RQ-C 매핑 **18개 item_id**다. `docs/n6_light_tasks_2026-10-26.md:71–101`의 엄격층 규칙을 유지한다. seed·후보·클래스 반복은 결함 수를 늘리지 않는다. 매핑된 취약 버전의 버그 위치 L1만 세고, 위치 모호성·관측 없음·준비 실패를 L1로 바꾸지 않는다. 구성 입력 탐색층, inference, banyan은 이 결론에서 제외한다. 고친 버전과 leave-one-out은 별도 대조군이다.

`N = 마감 뒤 S+J의 엄격층 L1 결함 − 기존 W의 엄격층 L1 결함`으로 고정한다. 기존 W 기준은 해시가 고정된 `docs/n6_light_rqc_strict_2026-10-26.json`이다.

| 완료된 비교 결과 | 결론 |
|---|---|
| N이 비어 있음 | 탐지 효용 미확인 |
| N 중 하나 이상을 같은 총시간 W가 관측하지 못함 | 탐지 효용 있음 |
| N의 모든 결함을 같은 총시간 W도 관측함 | 같은 시간이면 차이 없음 |

결함별 W 관측 여부를 함께 남긴다. 일부만 W에서 관측되면 첫 번째 효용 조건의 “하나 이상”을 적용한다. **S/J, 필수 W 또는 W 후보의 엄격층 확인이 미완료이면 결론은 대기**다. 미완료를 W의 미관측으로 바꾸지 않는 보수적 선택이다.

## 같은 총시간 W

필수 비교는 N을 낸 리비전에 한정한다. 리비전별 `T = 준비 + 세 seed의 S 퍼징 + J` 실측 wall time을 합친 뒤 같은 seed `2026100601/02/03`에 각각 정확히 T/3을 배정한다. 리비전 공유 준비는 한 번, seed별 준비는 실제 수행한 만큼 한 번씩 센다. 단계 안의 실패·재시도·정리 비용을 포함하고, 대기 시간은 제외한다. 중복·겹치는 영수증이나 빠진 단계가 있으면 비용 계산을 거부한다. 서로 다른 단계의 부모/자식 시간을 중복해서 더하지 않는다.

W 전체 회로·도구·소스·seed·메모리는 해당 원래 W 명세를 유지한다. 예산과 whole 시도 상한만 T/3으로 바꾼다. 45개 기존 명세의 메모리 상한은 모두 **10 GiB**였다(`round4c/original-W-controls.json`). S는 **600초/seed·30초/시도**와 고정 정책 B를 유지한다. W 후보도 같은 엄격층 L1 기준으로 확인한다. 이 확인 비용은 별도 보고하고 W 퍼징 배정에서 몰래 빼지 않는다.

선택 비교는 기존 매니페스트의 **15리비전 전체**다. 필수 비교·결론을 마친 맨 마지막 단계에 둔다. 사람이 `--optional-all-15-human-start`로 따로 시작해야 하며 자동 연쇄 실행하지 않는다. 선택 결과로 필수 비교를 대체하거나 기준을 바꾸지 않는다.

시간 추정: 필수 W 퍼징은 `Σ(새 L1 리비전의 T)`, 선택 전체 W는 `Σ(15리비전의 T)`에 W 준비·종료·후보 확인 시간이 추가된다. 세 seed가 모두 600초를 쓰는 경우 전체 S 퍼징 배정은 **27,000초=7.5시간**이고, 전체 W 배정에는 그 위에 S 준비·J 실측 시간이 더해진다. 아직 없는 J 시간과 디스크 peak는 숫자로 꾸미지 않는다. W는 측정 근거가 있는 peak/보존 byte가 없으면 시작하지 않으며 여유 관문은 `max(20 GiB, ceil(1.2×peak)+보존분)`이다. 명령 하나가 감시기의 3시간 한도를 넘으면 예산을 자르지 않고 보류한다.

## 증명 종류

앞으로 새 표에서는 아래 두 열을 합쳐 “제외” 한 숫자로 쓰지 않는다. 클래스 발생 수·요청 수·결함 수도 섞지 않는다.

| 열 | 포함 근거 | 뜻 |
|---|---|---|
| 입력과 무관한 증명 | 원뿔 불충족, 상수 불일치, 비트 범위, 가정 술어 불충족 | 증명식이 구성 기준 입력 값을 고정하지 않음 |
| 구성한 입력 기준 반박 | `local_constraint_refutation` | 구성 기준 입력의 나머지 값이 고정된 문맥에서만 반박 |

“입력과 무관”은 **후보 값과 무관하거나 모든 후보/실행을 증명했다는 뜻이 아니다**. 저장된 증명 근거를 분류하는 것이며 이번에 독립 증명기를 실행하지 않았다. 원뿔·비트 범위·술어의 소스 근거는 `docs/n6_light_tasks_2026-10-26.md:52–61`에 고정 커밋 `8065e2b` 기준으로 적혀 있다. 모르는 사유는 별도 미분류이며, 일반 `excluded` 문자열만으로 증명 종류를 추정하지 않는다. aq 재집계는 마감 뒤 단계에 둔다.

## 실행 경계와 남은 입력

`scripts/s_round4c_sequence_20261027.py`는 새 순서·W 계획·W 실행·결론 검사를 제공한다. 기존 4b의 준비/재현/S/새 J 경로는 변경하지 않는다. 새 W 실행은 마감, 명시적 `--execute`, SHA 고정 입력, 측정된 공간 계획을 모두 요구한다. 현재 실제 실행은 하지 않는다.

새 엄격층 채점 연결은 아직 필요하다. 원래 `scripts/n6_light_rqc_20261026.py:20–21,223,255–256`은 v1/v2.2·기존 결과 schema·완료 765건을 고정한다. 이를 v2.3 결과에 그대로 돌려도 된다고 가정하지 않는다. **새 입력 검증/채점 어댑터가 원래 채점 함수를 유지하면서 새 엔진·schema·분모를 연결해야 한다.** 현재 W 계획기는 완결되고 SHA로 묶인 엄격층 입력 검증 영수증이 없으면 진행하지 않는다. 이것과 4c 본문 확인 전에는 전체 실행 체인 완료나 v2.3 평가 동결을 선언하지 않는다.

**확인한 것:** 사전 고정된 기준과 원래 W 메모리·seed, 기존 코드의 엄격층 입력 제한. **추정한 것:** 향후 준비/J 시간과 공간 요구; 실제 탐지 효용은 아직 판단하지 않았다.
