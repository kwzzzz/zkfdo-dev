## 채택과 표본

v2.3 채택 관문은 **모든 replay 표본에서 v2.2와 판정 종류 및 사유가 일치**하는 것이다. 한 요청이라도 다르면 v2.3을 평가에 사용하지 않고 전체 순서를 멈춘다. 경로·시간·캐시 이름은 비교하지 않는다. J 호출 cargo 검사 **24개**도 v2.3 바이너리와 이번 새 캐시 경로에서 통과해야 한다. 검사 실패도 전체 순서를 멈춘다.

표본은 결과 판정이나 RQ-C·버그 위치를 보지 않고 아래 순서로 정한다. 실행기는 SHA가 맞고 요청·입력·완료 결과가 온전한 행만 채택하며 부적격 행은 같은 규칙의 다음 행으로 대체한다. 누락된 완료 결과를 음성 판정으로 취급하지 않는다.

1. Banyan S의 수정 버전: 요청 번호 오름차순으로 **24개 전체**.
2. Banyan S의 버그 버전: 요청 번호 오름차순으로 최대 **108개**. 선택한 행들의 과거 기록시간 합이 3시간에 도달하기 전까지 선택한다. 다음 행을 더하면 3시간을 넘는 경우 거기서 끝낸다. 3시간은 이 **표본량 규칙**이며 마감 뒤 프로세스 감시 한도가 아니다.
3. aq 완료 요청: 최종 state 사본에서 기록된 요청별 peak가 작은 순, 동률이면 요청 번호순으로 **5개**. 완료·입력·SHA 관문을 통과하지 못하면 같은 순서의 다음 행을 사용한다.

Banyan은 개발 사례이며 사전 등록된 18개 결함의 효용 결론에는 넣지 않는다. aq·B의 결과, RQ-C 매핑, zkbugs 지식은 표본·순서·채택 기준에 사용하지 않는다. RQ-C 고정 18항목/26행 매핑은 **엄격층 결과 채점에만** 사용한다.
