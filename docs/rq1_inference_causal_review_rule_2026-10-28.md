# inference L1 원인 귀속 재검토 규칙 (2026-10-28)

이 규칙은 **결과가 알려진 A 개발 자료를 사후 검토하는 규칙**이다. N5의 고정 판정이나 기존 L1/L2 기록을 바꾸지 않으며, 사전 등록 평가라고 부르지 않는다.

1. 입력은 `inference-original`의 기존 엄격 J L1 43요청, 원본 소스, 기존 L-06/L-07의 선택 수정·leave-one-out 기록이다. B, 새 퍼징, 새 J, 새 컴파일은 쓰지 않는다.
2. 검토 단위는 요청·후보·인스턴스가 아니라 **원본 소스의 결함 메커니즘**이다. 먼저 양성 조건별로 한 대표를 고른다. 가정 술어는 `(정확한 호출 인스턴스, 술어)`마다 `shared_from=null`인 요청 중 요청 SHA 사전순 첫째, TCCT는 `(대표 소스 템플릿, 위반 방식)`마다 원본 검증 영수증이 있는 요청 중 같은 순서의 첫째다. 이 선택은 중복을 줄일 뿐 원인 수를 정하지 않는다.
3. `검토 확인`은 대표의 원본 O0 제약·snarkjs 통과와 의미 위반, 원본 소스의 결함 식, **같은 의미 조건의 선택 수정 또는 leave-one-out 대조**, 다른 결함의 hint에만 의존하지 않는다는 근거가 모두 있을 때만 붙인다. 수정본에서 후보가 안 나왔다는 사실만으로 배제 증명을 대신하지 않는다. 공개 입력 변경은 별도 조건으로 표시한다.
4. 소스와 과거 L-06/L-07 메커니즘이 같아 보여도 대표 요청의 반례가 그 대조와 직접 연결되지 않으면 `메커니즘 관련, 요청 원인 미입증`이다. 근거가 더 모자라면 `미판정`이다. 연쇄 효과는 독립 원인으로 더하지 않는다.
5. 사람 검토 고유 원인 수 H는 `검토 확인`된 서로 다른 소스 메커니즘만 센다. 43요청의 완전한 H를 주장하려면 모든 양성 부류가 이 규칙으로 검토되어야 한다. 미검토 부류가 있으면 **부분 확인 하한**만 보고한다. 기계 군집 12·10을 H로 사용하지 않는다.

각 대표에는 요청·결과 SHA, 양성 조건, 소스 위치, 수정/LOO 근거, 공개·사설 입력 조건, 결론과 빠진 증거를 값 없이 남긴다. 원시 입력·witness는 기존 ignored `runs/`에 둔다.
