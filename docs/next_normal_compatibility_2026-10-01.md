# 다음 정상 호환성 실행 인계

작성일: 2026-10-01 · 담당: miiz · **인계 준비 완료·미착수**. 이 파일을 작성한 것만으로 실행 결과가 생기거나 N4-1 전체 관문이 통과한 것은 아니다. [논문 근거 색인](paper_evidence_index.md), [현재 체크포인트](../reports/research-checkpoint-2026-10-01/REPORT.md), [현재 계획](plan_revision_2026-10-01.md)을 기준으로 한다.

## 이번 한 질문

**O0·scalar에서 확인한 자동 wrapper 정상 계산 대응이 O1과 작은 배열 인터페이스에서도 성립하는가? 안 되면 어디서, 왜 지원 범위가 끊기는가?**

이것은 정상 동작의 지원 경계를 확인하는 개발 실험이다. 결함 탐지 실험·일반 의미 동등성 증명·독립 평가가 아니다. 실제 프로젝트에 적용할 컴파일 설정을 확정했다는 뜻도 아니다.

## 구현 담당에게 전달할 작업

AGENTS.md와 기존 정상 실행의 REPORT·SCOPE·측정 스크립트를 읽고, 짧은 새 실행 범위를 기록한 뒤 바로 구현·실행한다. 기존 보고서·실행 산출물·측정 코드 v1의 해시는 보존한다. 새 파일을 사용하며 이전 결과를 덮어쓰지 않는다. 반복적인 계획 검토를 선행 조건으로 추가하지 않는다.

1. **조건표:** 기존 정상 discovery fixture, 기존 반복/상이 파라미터 산술 통제, 결함 없는 작은 배열 산술 통제 1개를 사용한다. 정상 입력은 대상별 3개를 실행 전 정한다. O0/O1의 3×2 조건을 기본으로 하며 O2·새 프로젝트·추가 정상 회로를 계속 늘리지 않는다. 지원하지 않는 대상도 조건표에서 삭제하지 않는다.
2. **자동 구성:** 기존 discovery/wrapper 생성 경로를 사용한다. 배열 통제는 원본 main 안에서 동일·상이 파라미터 하위 인스턴스를 사용하는 정상 산술로 제한한다. 사람이 wrapper를 작성해 자동 구성 실패를 가리지 않는다.
3. **실제 실행:** 원본과 wrapper를 같은 해당 옵션으로 컴파일하고 정상 계산, 생성 할당의 R1CS 검사, 대응 가능한 경계 비교를 수행한다. 정상 제약을 누락·변형하거나 비정상 할당을 만들지 않는다.
4. **대응 상태:** 원본/조각 컴파일 성공, 정상 계산 성공, 제약 만족, 경계 대응·일치 여부를 별도 상태로 남긴다. 최적화로 제거된 신호, 배열 모양, 이름/인덱스 대응 실패는 이유와 개수를 기록한다. 출력만 일치한다고 확인 못 한 내부 경계를 성공으로 채우지 않는다. 0 대입·추측·조용한 생략은 하지 않는다.
5. **최소 코드 변경:** O0 전용 flags/입출력 처리에 필요한 제한된 매개변수화와 정상 배열 대응만 구현한다. 범용 최적화 역복원이나 컴파일러 교체가 필요하면 해당 조건을 미지원으로 남기고 종료한다. 범위를 넓히기 위한 새 검토 보고서를 시작하지 않는다.
6. **측정:** 전체 조건의 대상/호출 위치/구성 수, 컴파일·계산·검사 성공/실패, 경계 대응 분모와 일치, 실제 준비/정상 검증 시간을 남긴다. 이번은 호환성 실험이므로 반복을 늘려 속도 우위를 주장하지 않는다. 캐시·옵션·버전·순서를 기록한다.
7. **집계 독립성:** 기존 정상 실행처럼 원본 도구 ledger로 결과를 산출한다. 오프라인 집계기 코드와 관련 테스트는 수정하지 않는다. 미지원은 탐지 음성이 아니다.
8. **검증과 산출:** 의미 있는 정상 회귀 검사와 AGENTS.md 필수 코드 검사를 수행한다. `reports/n4-1-normal-compatibility-2026-10-01/REPORT.md`에 6조건 전체 표와 제한을, 같은 디렉터리의 `evidence.json`에 값 없는 경로·hash·판정·시간을 남긴다. 원시 입력·할당·컴파일 산출물은 ignored `runs/`에 둔다. 기존 경로가 있으면 새 버전을 사용한다.
9. **끝내는 조건:** 첫 고정 조건표를 모두 시도해 성공/실패/미지원으로 설명하고, 코드 변경으로 바뀐 조건만 필요한 만큼 재확인하면 이번 실행을 종료한다. O1에서 실패했다고 O2나 새 mapping 기법으로 계속 확장하지 않는다. 현재 N4-1 상한의 사용 기록을 갱신하고 소요를 모르면 추정값을 실제 사용량으로 쓰지 않는다.

코드·실험 결과가 나오면 [논문 근거 색인](paper_evidence_index.md)에 새 `NC-01` 행을 추가한다. 빈 성공 행을 미리 만들지 않는다. 계획의 N4 상태는 담당 miiz로 갱신하되 N4-1 전체·N4-2·N5 상태를 과장하지 않는다. commit/push/PR은 하지 않는다.

## 완료 보고 형식

첫 부분에 대상 × O0/O1의 실제 결과표를 둔다. 이어 새로 입증한 범위, 지원 밖/실패의 원인, 최소 수정과 확인 근거, 다음 비교 가능성 판단에 주는 영향을 적는다. 정상 대응 검증이 결함 후보의 원인 귀속·abort·A안 공정성을 입증하지 않는다는 제한을 유지한다.

기록·집계 수정 작업은 후속 정상 실행의 선행 대기 작업이 아니다. 새 실험에서 실제 차단 오류를 발견했을 때만 해당 부분을 다시 연다. 정상 호환성 결과가 나오기 전부터 새로운 후속 캠페인을 병렬로 확대하지 않는다.
