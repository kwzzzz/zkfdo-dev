# NC-01 이후 다음 한 단계

2026-10-02 · 담당 miiz · 버전 `next-step-v1`. 상태: **인계 준비 완료, 아래 새 구현·실행은 미착수**. 한 번에 전체 연구를 마치지 않고 단계별 결과를 보고 후속 범위를 정한다. N3의 주 기여 가설과 N5 미고정 상태는 유지한다.

## 목적과 현재 위치

최종 연구 질문은 실제 entrypoint의 자동 컴포넌트 구성으로 적용 범위·검토된 발견·총비용이 어떻게 달라지는가이다. 현재 구현은 기존 컴포넌트 경계를 따라 구체 인스턴스를 찾고 wrapper를 만드는 방식이다. 임의의 회로를 새 경계로 자르는 일반 알고리즘이 아니다. 구현의 존재와 연구적 신규성, 개발 자료에서의 성공과 독립 평가 성과를 구별한다.

[NC-01](../reports/n4-1-normal-compatibility-2026-10-01/REPORT.md)은 이미 완료했다. O0의 정상 경계는 45/45 일치했고, O1은 15/45 일치·30 미지원이다. O1도 컴파일·정상 계산·제약 검사는 모두 성공했으며, 미지원 원인은 최적화로 제거된 직접 관측 신호다. 이를 분해 실패·값 불일치로 쓰지 않는다. NC-01의 여섯 조건을 다시 실행하는 작업은 요청하지 않는다.

NC-01의 `adapter(case, prefix, value)`는 fixture 이름과 호출 경로에 따른 수동 입력 공식을 사용한다. 이것은 기존 검사의 명시된 통제 조건이며 오류가 아니다. 다음 작업은 **정상 대응 검사의 이 수작업을 제거할 수 있는가**를 묻는다. 기존 wrapper 생성 자체가 수동이라는 뜻도, 이 작업이 새로운 탐지 기법이라는 뜻도 아니다.

## 이번 한 질문

**이미 사용한 세 정상 fixture의 O0 범위에서, 원본의 검증된 정상 witness와 직접 신호 대응으로 각 컴포넌트의 입력을 자동으로 가져와 wrapper를 다시 계산하고 원본 출력 경계와 비교할 수 있는가?**

완료하면 원본 정상 실행 → 자동 호출 위치 대응 → 조각 입력 구성 → 독립 정상 계산 → 출력 비교라는 경로의 제한된 증거가 생긴다. 정상 입력 합성, 모든 입력의 의미 동등성, 결함 후보 투영, 호출 맥락의 일반 판정, 탐지 우위는 이번 결과로 주장하지 않는다. 원본 실행을 위한 입력 세 개씩은 기존에 고정한 값을 그대로 사용한다.

사전 분모는 원본 입력 조건 9개와 호출 위치×입력 경계 45개다. 실행 실패·미지원으로 시도하지 못한 항목도 이 분모에 남긴다. 같은 fixture를 재사용하므로 NC-01에 독립 사례가 추가된 것으로 합산하지 않는다.

O0는 이번 개발 실험의 범위다. 평가 전체의 컴파일 옵션을 고정하거나 O1 문제를 해결했다고 선언하지 않는다. O1 신호 복원은 별도 증거가 필요한 후속 선택사항으로 남긴다.

## 병렬 역할과 파일 소유

| 역할 | 맡는 일 | 수정 범위 | 종료 조건 |
|---|---|---|---|
| 구현 담당 | 기존 정상 자료에서 자동 경계 입력 연결을 구현하고 실제 실행 | 새 측정 스크립트·회귀 검사·새 실행 보고서, 완료 후 현재 안내/진행 표/색인 | 세 fixture × 기존 입력 세 개의 O0 전체 조건을 한 번 시도하고 성공·실패·미지원 이유 기록. 최소 수정에 영향받는 조건만 재확인 |
| 검토 담당 | 같은 작업의 정확한 수용 조건과 실패 사례를 코드 구현과 독립적으로 정리 | 새 `reports/normal-boundary-replay-contract-2026-10-02/REVIEW.md` 한 파일 | 최대 두 쪽의 수용 표와 한계. 기존 코드의 완료 판정이나 새 구현의 통과 판정은 하지 않음 |

공유 진행 표는 구현 담당만 갱신한다. 검토 담당은 자신의 보고서에서 작업 완료를 알린다. 구현이 끝나면 파일 해시를 고정한 해당 변경만 후속 확인할 수 있지만, 그 검토를 지금 실행하거나 전체 기록/집계 경로의 재감사로 확대하지 않는다.

## 구현 담당에게 전달할 프롬프트

저장소 AGENTS.md, reports/START_HERE.md, docs/plan_revision_2026-10-01.md와 docs/next_step_handoff_2026-10-02.md를 읽고 다음 한 작업을 수행하라. 담당은 miiz로 기록하고 시작/완료를 현재 계획의 N4 행에 반영하라.

목적은 정상 대응 검사의 fixture별 수동 입력 공식을 자동 경계 입력 연결로 대체할 수 있는지 실측하는 것이다. NC-01은 완료됐으므로 기존 여섯 조건을 그대로 반복하지 않는다. 기존 정상 fixture 세 개·각각 사전 입력 세 개와 O0만 사용한다. 실제 암호 구현이나 새 프로젝트를 추가하지 않는다.

1. NC-01의 REPORT/SCOPE/evidence와 측정 스크립트를 읽고 새 범위·입력 목록·도구/소스 해시를 실행 전에 기록한다. 이전 측정 코드와 고정 보고서는 보존한다. 새 파일과 ignored runs의 새 경로를 사용한다.
2. 기존 discovery와 wrapper 생성 경로를 이용한다. 원본 정상 계산과 전체 witness 제약 검사가 성공한 경우에만, 직접 신호 대응에서 해당 호출 위치의 입력을 읽어 wrapper 입력을 구성한다. fixture 이름·호출 경로에 따른 offset 공식/예외 목록을 새 실행 경로에 넣지 않는다. 기존 함수는 결과가 동일한지 대조할 수 있으나 새 입력의 공급원으로 쓰지 않는다.
3. 지원 범위를 기존 `in/out` scalar/1차원 배열 인터페이스로 명시한다. 입력 연결 한 경로만 구현하고 범용 인터페이스 추출 체계를 새로 만들지 않는다. 배열 모양·필수 입력·호출 경로·동일 구성의 서로 다른 호출 위치를 확인한다. 신호 결측·음수/범위 밖 index·모양 불일치·모호한 대응을 추측이나 0으로 채우지 않고 이유 있는 미지원/실패로 남긴다. 범용 parser·컴파일러·최적화 역복원이 필요하면 그 조건을 미지원으로 기록한다.
4. 입력만 전달하고 wrapper의 witness와 출력은 정상 계산기로 새로 계산한다. 원본 출력을 wrapper 출력으로 복사하여 비교가 성공하게 만들지 않는다. 양쪽 전체 witness 제약 검사와 출력 경계 비교를 수행한다. 같은 정상 witness에서 가져온 입력의 재확인과 독립적으로 다시 계산한 출력의 일치를 서로 다른 증거로 기록한다.
5. 자동 구성, 입력 연결, 정상 재계산, 제약 검사, 출력 비교의 분모와 상태를 따로 기록한다. 준비·원본 계산·입력 연결·wrapper 계산/검사 비용을 분리하되 소수 측정으로 속도 우위를 주장하지 않는다. 원시 값은 ignored runs에만 보존한다.
6. 의미 있는 실패 경계 회귀 검사를 추가하고 AGENTS.md의 fmt·지정 clippy·cargo test와 해당 Python 검사를 수행한다. 보존 파일 해시도 확인한다. 검토 담당 보고서가 도착하면 실제 결함에 해당하는 지적만 반영하고 변경한 조건만 재검증한다.
7. 결과를 reports/n4-1-normal-boundary-replay-2026-10-02/REPORT.md와 evidence.json에 남긴다. 이름이 이미 쓰였다면 새 버전을 만든다. 논문 색인에 NB-01로 연결하고 현재 안내/계획을 동기화한다. N4-1 전체 완료·N5 고정으로 승격하지 않는다.

종료 기준은 세 fixture × 세 입력의 사전 조건을 모두 설명하는 것이다. 실패를 감추기 위한 수동 wrapper·입력 공식으로 대체하거나, 성공 사례를 계속 추가하지 않는다. 새 결함 후보 생성·퍼징·취약점 재현·평가 대상 준비는 이번 작업에 포함하지 않는다. 기존 record/aggregate 코드와 검토 담당 파일은 수정하지 않는다. 문서 작성자/담당 귀속에 도구 이름을 넣지 않고 commit/push/PR은 하지 않는다.

기존 N4-1의 담당자 작업 상한 12시간을 유지한다. 과거 사용시간은 unknown이므로 잔여 시간을 임의로 계산하지 않는다. 이번 작업의 확인 가능한 소요를 기록하고, 상한 확인이나 범위 초과 문제가 생기면 구현 범위를 늘리기 전에 그 사실과 현재 결과를 보고한다.

최종 보고는 '무엇을 위해 했는가 → 조건별 결과 → 자동화된 부분 → 남은 수작업/미지원 → 주장 가능한 범위 → 다음 결정 한 가지' 순서로 작성하라.

## 검토 담당에게 전달할 프롬프트

저장소 AGENTS.md, 현재 계획, docs/next_step_handoff_2026-10-02.md 및 완료된 NC-01 REPORT/SCOPE와 scripts/measure_normal_compatibility.py를 읽어라. 병렬로 구현 중인 정상 경계 입력 연결의 수용 기준만 정리하라. 새 구현의 작업 중 파일을 따라가며 판정을 바꾸거나 코드/공유 문서를 수정하지 않는다.

목적은 '수동 입력 공식이 없어졌는가'와 '그 정상 실행이 무엇을 입증하는가'를 구현 담당이 확인할 수 있게 만드는 것이다. 새 reports/normal-boundary-replay-contract-2026-10-02/REVIEW.md 한 파일에 최대 두 쪽으로 아래 여섯 항목의 통과/실패/미지원 조건과 필요한 증거를 적어라.

1. 원본 정상 실행 및 전체 제약 검사의 선행 성공과 입력 출처 연결.
2. 구체 파라미터·배열 모양·호출 위치의 구분. 같은 컴파일 구성 재사용이 같은 호출 맥락을 뜻하지 않는다는 점.
3. 새 경로에서 fixture별 offset/경로 예외/기존 adapter 값에 의존하지 않는지 확인하는 방법.
4. 입력의 출처 일치와 wrapper에서 독립적으로 계산한 출력 일치를 구별하고 순환적인 성공 판정을 피하는 조건.
5. 결측·최적화 제거·index 오류·부분 배열·대응 모호성을 성공이나 불일치로 조용히 바꾸지 않는 조건.
6. 성공 후 사용할 수 있는 문장 한 개와 아직 사용할 수 없는 주장: 범용 정상 입력 합성, 모든 입력의 의미 보존, 결함 후보 판정, 프로젝트 결함, 탐지 우위.

과거 집계 재감사, 새 문헌 전수 조사, 추가 fixture/프로젝트, 후보 실행은 하지 않는다. 이 문서는 사전 수용 기준이며 신규 구현을 검증한 보고서가 아니라고 명시한다. 기존 고정 기록·판정과 진행 표를 수정하지 않고, 담당 귀속에 도구 이름을 넣지 않는다. commit/push/PR은 하지 않는다. 작성이 끝나면 완료하고 구현의 최종 스냅샷 확인은 다음 인계로 남겨라.

## 그다음은 결과를 보고 결정한다

이번 결과를 받은 뒤 정상 예제를 계속 늘리기보다, 기술적 차별성에 필요한 미해결 항목과 비교 실행의 수집·자원·판정 준비를 분리해 가장 작은 다음 작업 하나를 고른다. 정상 경계 재실행만으로 N4-1의 시간/자원 공정성·같은 수준 판정·귀속·맥락 문제는 해결되지 않는다.

이후 큰 흐름은 N4의 남은 준비 → N5의 대상/규칙/도구 고정 → 고정 범위의 평가 → 적용성·검토된 결과·비용과 실패 사례를 함께 분석하는 것이다. 현재 문서는 후속 평가 실행을 한꺼번에 지시하지 않는다. 성공을 전제하거나 '최초 분해'를 논문 기여로 확정하지 않는다.
