# 10월 29일 교수님 중간 점검: 현재 기여와 12월까지의 검증 계획 — v2

2026-10-28. [v1](contribution_brief_2026-10-29_v1.md)은 자리의 성격이 미확인이라고 적었다. 사용자가 확인한 목적은 **완성 논문 발표가 아니라**, 현재 방법·결과를 보고 교수님이 연구의 기여 각도와 12월까지 도달 가능한 수준을 판단하는 것이다. 이 문서는 발표를 새 평가 마감으로 만들거나 고정 N5 판정 규칙을 바꾸지 않는다.

## 교수님께 먼저 보여 줄 주장

> “우리는 큰 Circom 원본을 통째로 퍼징하기 어려울 때 구체 부품 호출을 자동으로 찾아 퍼징하고, 조각 후보가 실제 원본 호출 위치에서 도달하는지 확인하는 S+J를 만들었습니다. 특히 부모가 계산한 중간값이 부품 입력일 때 최상위 입력을 합성해 원본 전체 제약을 통과하는 반례로 연결합니다. 후보 **값**의 불가능과 같은 **위반**의 불가능도 구분합니다.”

이것은 **방법 기여 후보**다. 자동 분할·반례 상위 전파의 일반 아이디어는 ScaleCirc 등 선행에 있고, zkFuzz의 퍼징도 선행이다. 차이는 구체 호출 인스턴스의 퍼징 신호와 원본 맥락의 도달·배제·미판정을 연결하는 실행 계약에 있다. [ScaleCirc 원문 대조](scalecirc_primary_comparison_2026-10-28.md)의 전체 backend fallback을 포함한 우위는 아직 측정하지 않았다.

## 교수님께 받을 판단

1. 위 방법 계약과 계산된 입력 사례가 **논문의 중심 질문**으로 충분히 선명한가? 아니라면 12월까지 어떤 성능·정확성 결과가 최소 필요할까?
2. 우선 검증을 **독립 B의 원본 검증 결과·고유 원인/총비용**에 둘지, **ScaleCirc 공식 UNDER 경로(전체 fallback 포함)의 동일 속성 비교**에 둘지 정한다. 둘 다 필요하더라도 선행 순서를 정한다.
3. 12월 원고의 범위를 현재 시스템의 end-to-end 평가로 잡을지, 기여가 좁으면 호출 맥락 판정의 의미·보장 연구로 좁힐지 의견을 받는다. 지금 논문 등급을 확정해 달라는 자리가 아니다.
