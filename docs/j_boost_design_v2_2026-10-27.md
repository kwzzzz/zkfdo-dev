## 1. 경쟁안 ④: 정방향 계산 + 그 자리 국소 풀이

상위 입력을 기준값 → 0·1·p−1 및 증명된 경계값 → 고정 seed 무작위 순서로 선택한다. 정상 계산으로 얻은 호출 입력 z를 고정하고 `C_s(z,u) ∧ V_s(z,u)`를 푼다. 출력/내부 모델은 원본이 허용하는 hint 제어로 실현한 뒤 아래쪽을 계산하고 전체 R1CS·최상위 영향을 검사한다. 출력이 직접 hint가 아니거나 정상 계산으로 모델이 사라지면 재현 실패로 기록한다. 국소 SAT를 원본 도달로 세지 않는다.

**결정: ④를 ③의 제한된 첫 단계이자 독립 비교군으로 둔다.** ③의 전체 검색 예산 중 사전 고정한 20%까지만 ④에 사용하고 남은 예산으로 조건 탐색·정제를 한다. ④ 단독 비교군은 같은 전체 예산을 사용한다. 따라서 ③은 두 방법의 예산을 합쳐 받지 않는다. 20%는 초기 설계값이며 최종 평가 전에 A에서 고정한다.

현재 `predicate.rs:479–498`은 기준 입력에서 시작하지만 `inputs_free=true`, `pinned=empty`로 `repair::search`를 호출한다. `repair.rs:1362–1390`에서 국소 질의를 하고 `:1468–1487`에서 상위 경로까지 넓힌다. **④와 첫 동작 일부는 겹치지만, 호출 입력을 계속 고정한 정방향 표본 탐색 전용 구현은 아니다.** 기존 기능을 ④라는 새 발명으로 세지 않는다.

W와는 정상 입력·변이 실행·전체 제약 검증을 사용한다는 점이 같다. W는 전체 회로에서 위치와 변이를 탐색하고, ④는 S가 지정한 위치·같은 술어를 대상으로 국소 solver를 사용한다. ④에는 위치 정보와 solver 비용이라는 차이가 있으므로 W 대비 결과를 J만의 효과로 돌리지 않는다. 전체 S+J 비용도 따로 비교한다.

**가장 강한 반박:** 흔한 입력에서 위반이면 ④로 충분하다. **답:** 맞다. ④와 ③의 검증된 결론·비용이 같다면 역합성·core 선택·잔차 정제가 필요하다는 주장을 철회한다. 나머지 주장은 준비/지원 범위 등 실제 입증된 것에 한정한다.

## 2. 좁은 위반 조건의 탐색

부품 입력 z, 내부/출력 u, 부품 원본 제약 C_s에 대해 `Bad_s(z) ≡ ∃u. C_s(z,u) ∧ V_s(z,u)`를 정의한다. 한 로컬 모델의 z 전체를 다시 고정하지 않고 **위반 관계 자체**를 상위 질의에 공유한다. 안전한 소거/논리 단순화가 가능하면 `Bad_s`의 식을 얻고, 불가능하면 u를 존재변수로 남긴 관계를 사용한다. 모델 한 개에서 추측한 ‘분모=0’은 필요충분 조건으로 쓰지 않는다. 연산식과 제약 구조로만 분석하고 부품 이름별 규칙을 두지 않는다.

상위 탐색은 원본 관계의 부분집합 `C_up(x,z,...)`와 `C_s∧V_s∧H`를 함께 푼다. 특정 S 값 `z=c`의 원상 찾기와 달리 **Bad_s를 만족하는 어떤 z와 그에 연결된 x**를 찾는다. 위에서 생성한 값들은 아래의 동일 위반 관계를 만족해야 하며, 아래에서 제안한 값들은 원본 전체를 만족해야 한다. 비선형 역산이 계속 어렵다면 unknown이다.

배제는 `C_up ∧ C_s ∧ V_s ∧ H`에서 **모든 임시 기준값/표본 고정/반복 차단을 제거한 UNSAT**여야 한다. 사용한 관계가 원본으로부터 함의되고 V가 정확히 보존되면 부분 제약의 UNSAT로 충분하다. H가 고정된 공개 입력을 포함하면 그 조건부 배제이며, 전체 회로 안전이나 다른 위반 종류의 부재가 아니다. Bad_s를 과소근사한 식으로 바꾸었다면 그 식의 UNSAT로 V 전체를 배제할 수 없다.

예: `q <-- a / d; q*d === a;`에서 S의 0 나눗셈 의미는 §4의 참조값 0이다. d=0,a=0에서 다른 q가 허용될 수 있지만, 출력 연결/다른 제약까지 있어야 출력 위반이다. d=0이라는 조건만으로 일반 위반을 단정하지 않는다.

**가장 강한 반박:** 정확한 Bad_s 계산 자체가 전체 풀이만큼 어렵고, 관계를 합치면 결국 SMT 아닌가. **답:** 그럴 수 있다. 소거를 필수로 두지 않고 관계를 공유하며, ②·④와 같은 예산으로 비교한다. ‘역산을 없앴다’가 아니라 ‘불필요한 특정 값을 고정하지 않는다’는 방법이다.

## 4. 위반 술어의 고정 정의

확인한 S 구현: `.external/zkFuzz/src/mutator/mutation_test_trace_fitness_fn.rs:74–98`은 같은 입력의 원래 trace를 계산하고, `:190–213`은 **대상 부품 출력**만 mod p로 비교하여 `NonDeterministic`을 반환한다. hint 값의 차이는 이 출력 판정과 같지 않다.

정상 참조 계산이 가능한 경우 `V_out(z,u) = C_s(z,u) ∧ (out(u) ≠ G_s(z))`다. 출력 벡터 중 하나라도 다르면 참이며 같은 부품 입력 z를 공유한다. 참조 의미는 S 오라클의 계산 의미다.

참조 실패 분기: `mutation_test_trace_fitness_fn.rs:111–125,172–188`은 trace의 check 실패와 side-constraint 만족을 `UnexpectedInput`으로 처리한다. `mutator/utils.rs:679–682,786–815`는 check 실패 위치를 남기며 계속 계산한다. 따라서 실패를 임의 출력과의 부등식으로 만들지 않고 **`V_unexpected`라는 별도 위반 종류**로 유지한다. `:87–90`의 emulate None(예: 인덱스 평가 불가)은 입력을 건너뛰며 위반으로 세지 않는다. 도구 오류도 위반이 아니다.

## 5. 구성 입력 기준 국소 반박 재확인

현재 `mod.rs:3544–3553`은 모든 main 입력을 고정하고 `:3560–3573`은 후보 site 값도 고정한다. `:3586–3600`의 direct/constant 분류는 무관한 main 입력 고정이 증명에 필요 없음을 검사하지 않는다.

재확인 질의는 `C_recheck ∧ B_s(w,c) ∧ H_contract`로 만든다. 구성 입력의 **후보가 결정하지 않는 모든 main 입력 고정을 제거**한다. 부품 입력과 연결된 main 입력도 단지 계산에 기여한다는 이유로 고정하지 않으며, 후보가 논리적으로 강제하는 등식만 원본 관계에서 도출한다. 공개 입력 고정 등 명시된 H_contract는 유지하고 보고한다.

UNSAT이면 원본이 C_recheck를 함의하고 목표 B_s와 대응이 정확한 경우에 한해 **불필요한 구성 입력 고정에 의존하지 않는 exact 후보 배제**로 새 기록을 남긴다. 모든 입력에 대한 같은 V의 배제를 말하려면 B_s 대신 V_s로 새 질의가 필요하다. SAT는 `recheck_not_refuted`이며 원본 전체 witness 검증 전에는 도달이나 기존 배제의 오류로 부르지 않는다. timeout/unknown은 기존 범위를 넓히지 않는다. 기존 ‘구성 입력 기준 제외’ 기록은 보존한다.

**가장 강한 반박:** 무관한 입력만 풀면 다른 고정에 대한 의존은 남는다. **답:** 후보가 정한 조건과 H를 모두 출력하고, exact 배제/술어 배제를 구별한다. 기존 verdict 이름을 바꿔 쓰지 않는다.

## 6. 독립 평가와 일곱 비교군

B는 v2.2 결과를 이미 본 비교 자료로 표시한다. 새 대상의 출처는 공개 Circom 저장소의 버전 고정 스냅샷이다. 수집 마감 시각·검색식·저장소 목록을 결과 실행 전에 고정하고, 기본 실행 진입점이 있고 라이선스/의존성 준비가 가능한 대상만 포함한다. A·B 및 개발에 사용한 저장소/리비전과 소스 동일·포크 중복을 제외한다. 결함 위치나 도구의 성공 여부로 고르지 않는다.

크기 층은 원본 O0 기준 ≤1,000 / 1,001–100,000 / >100,000 제약이다. 원본 compiler 성공·크기·지원 여부만으로 층화하고 저장소 URL → commit → entrypoint 경로의 사전식 순서로 각 층 앞 10개, 저장소당 최대 2개를 선택한다. 층이 부족하면 부족한 수를 보고하고 실패한 대상을 뒤의 성공 대상으로 대체하지 않는다. 새 대상 준비 실패도 분모다. 소스/제약 중복은 하나로 묶고 형제 포크의 개발 노출도 제외한다.

| 군 | 예산·지원 범위 | 주 지표 |
|---|---|---|
| ① 지금 J | 현재 요청 공유 sweep 20초 유지, 전체 요청 상한 공통 | 원본 검증 L1·도달·범위별 배제·unknown·총시간/RSS |
| ①′ 공정 예산 J | 클래스당 같은 sweep b, 요청 전체 상한도 공통 | 같은 지표와 클래스별 실제 배정/사용시간 |
| ② 전체 질의 | 동일 P,H·solver·seed·검색 총예산 T | 위와 같음; 전체 모델 확인 포함 |

J 비교 T는 작은/중간/큰 원본에 60/300/900초를 초기안으로 두며, 준비 포함 총비용을 따로 기록한다. 실제 ①′의 b 재배분은 총예산을 늘리지 않는 조건과 독립된 실험 요인이다. ①은 클래스당 균등하지 않음을 그대로 드러낸다. 비교는 같은 instance·P·H 단위로 중복 제거하고, 요청에 여러 class가 있으면 전체 상한을 모두에게 동일 적용한다. 새 seed는 평가 전에 3개를 고정한다. W/ScaleCirc는 속성이 다른 결과를 같은 성공으로 세지 않는다. RQ-C는 방법 설계·대상 선택에 쓰지 않는다.

**가장 강한 반박:** ③/④는 S의 위치 정보를 받아 W보다 유리하다. **답:** J 기전 비교와 S+J 전체 시스템 비교를 분리하고, 후자에는 S의 모든 비용을 합친다. B를 새 독립 검증 자료로 포장하지 않는다.

## 7. 개발 사례 선택

맥이 제공한 A 자료만 사용한다. source/요청이 금지 경로에만 있으면 필요한 경로를 기록하고 보류한다. 미판정은 `(cause_before_budget,b_outcome,원본 크기 층)`으로 나누고 각 층에서 요청 hash·class ID 사전식 순서로 첫 3개를 개발 진단에 사용한다. 직접 완성 측정은 `synthesis_model_not_reproduced`/`model_not_reproduced`인 제공 사례 **전부**, 국소 반박 재확인은 해당 사례 전부를 포함한다. 부품 이름·알려진 버그·RQ-C로 우선순위를 바꾸지 않는다.

**가장 강한 반박:** A에 맞춘 개선도 성과라고 쓰기 쉽다. **답:** A는 구현·원인 분석용이다. J 보강의 효과 주장은 최종 B 비교 및 미노출 새 대상으로 한정하며, B의 노출을 명시한다. 현재 제공 폴더는 없어 건수/개별 사례 대응은 비워 둔다.

## 8. 구현 범위와 주장 철회 조건

| 구분 | 작업 | 작업량 추정 |
|---|---|---|
| 이번 공통 기반 | 기존 SAT 모델의 직접 완성, 엄격 O0/O1 대응, 원본 검사·별도 결과 | 1–2 작업일 |
| 이번 공통 기반 | 공정 sweep 예산 옵션·기본값 불변·진단·합성/회귀 | 1–2 작업일 |

작업일은 집중 작업 6시간의 견적이며 설계 채택 기준이나 완료 보장이 아니다. 변경 전 백업, 옵션 기본 off, 기존 verdict 보존은 구현 계약이다. 1판 1·2절의 코드 조사 및 주입 진단, 4.2의 검색/증명 분리, 4.6의 건전성 의무는 그대로다. 직접 완성은 이미 얻은 모델을 검증하는 경로이며 새로운 선택적 정제를 이번에 섞지 않는다.

1판 평가의 (가)~(라)에 **(마) ④가 같은 예산에서 ③과 같은 결론을 얻고 비용도 열등하지 않으면 조건 역탐색·선택적 정제의 필요성/우위를 주장하지 않는다**, **(바) ③의 이득이 더 많은 예산·지원 오라클 차이로 설명되면 알고리즘 이득을 주장하지 않는다**를 추가한다.

**가장 강한 반박:** 공통 기반 세 개만 구현해도 논문 기여인가. **답:** 준비·정확성 기반이지 그 자체로 주요 기여 확정이 아니다. 새 방법을 공정하게 시험할 수 있게 만들고, 결과가 단순 경쟁안보다 나은지로 연구 주장을 결정한다.

## 확인한 것

- 현재 LessThan 검색·수리와 합성 실패 문자열·국소 반박 고정 위치를 정적 코드로 확인했다.

- aq 실행기는 고정 v2.2/v1 바이너리를 사용하며 확인한 실행 경로에 재빌드가 없다. 시작 SHA는 일치했다.
