# N7 A 대형 원본 cold S+J 끝까지 측정 v1 (실행 전 고정)

2026-10-29. 대상은 inference-original `src/circuit.circom`(O0 401,664제약, R1CS SHA `7efa0199…`) 한 회로다. 결과를 본 뒤 고른 회로이므로 민감도 시험이며, 독립 B 성과나 ScaleCirc 대비 우위로 승격하지 않는다. 기존 실행기·동결 엔진·J·판정 규칙·기록은 바꾸지 않는다.

## 실행기와 시간 경계

[실행기](../scripts/n7_a_sj_cold_e2e_20261029.py)는 seed 하나를 다음 순서로 끝까지 잰다. 시계는 원본 소스 복사 직전에 시작한다.

1. 원본 복사·트리 SHA 확인 → O0 컴파일 → 정직 witness → snarkjs 원본 검사
2. 자동 조각 준비(`targets` → manifest → `prepare small-first` → plan)
3. 조각 22개 preflight 컴파일. 이전 컴파일 캐시를 재사용하지 않는다(새 폴더, 실측 포함).
4. v4 엔진 퍼징: 조각당 최대 30초, 순환, 동시 실행 1.
5. 후보가 수집되는 즉시 고정 J로 판정한다. J 시간은 같은 절대 종료시각에서 빠진다.
6. 첫 검증 원인(J `entrypoint_violation`, Rust 불만족 0, snarkjs `correct`, J가 쓴 O0 R1CS SHA가 방금 컴파일한 원본과 같음)이 기록되면 멈춘다.

엔진·J 파일은 수정하지 않았다. 후보 수집 함수만 실행 중에 감싸서 J를 바로 부른다.

## 고정 규칙

- **상한:** seed당 절대 1,600초([v1 프로토콜](n7_a_equal_machine_time_protocol_v1_2026-10-29.md)과 같음). 상한 안에 J 판정이 끝나지 않은 후보는 인정하지 않는다(`unjudged_at_deadline`).
- **seed:** 2026100601 → 기록이 온전하면 2026100602, 2026100603. 운영 실패가 나면 다음 seed를 시작하지 않는다. 결과를 본 뒤 상한·seed·L1 정의를 바꾸지 않는다.
- **코어:** macOS에는 코어 고정 기능이 없다. 대신 W와 같게 무거운 프로세스를 한 번에 하나만 돌린다(퍼징 동시 실행 1, J 순차, 실행 전체 1개). 이 기계는 10코어다. 단계별 벽시계와 함께 자식 프로세스 CPU 시간(`RUSAGE_CHILDREN`)을 기록한다. 같은 것은 벽시계 상한이며 CPU 사용량은 다를 수 있으므로 함께 보고한다.
- **조각 순서:** small-first 계획을 (크기, 템플릿 이름, 구체 인자, target ID) 순으로 다시 정렬한다. 같은 크기의 순서가 실행마다 바뀌던 문제(AssertBit/Subtract)를 이름순으로 고정한다.
- **고유 원인:** 첫 검증 후보를 기존 IntDiv 한 줄 수정본(`units/inference-r-intdiv`)에 같은 요청으로 다시 판정한다. 수정본에서 J 준비가 성공하고 검증 원인이 0이면 IntDiv 원인으로 본다. 이 재생은 S+J 시간 밖에서 따로 잰다(상한 1,800초).
- **비교 기준(W):** 같은 회로 W 1,236.07초×3 seed 후보 0([n5_next_gate](n5_next_gate_2026-10-28.md) 34–36행)에 W 준비 시간 2.937초(O0 컴파일+정직 witness+snarkjs, [가능성 결과](n7_a_feasibility_results_2026-10-29.md))를 더한 **1,239.0초**를 seed별 기준으로 쓴다. W는 후보가 없었으므로 J 시간은 0이다.
- **환경:** `nice 19`, 시작 시 내장 디스크 여유 30 GiB 이상, 실행 중 18 GiB 미만이면 중지, 메모리 상한 10 GiB. B, aq 이미지·캐시, 버그 위치 목록은 쓰지 않는다.

## 사전 시험

합성 단위시험 3개 통과. 150초 상한 운영 시험 3회(`runs/n7-a-sj-cold-2026-10-29-smoke*`): 상대 경로·J source root 문제를 고친 뒤 세 번째에서 준비→퍼징→즉시 J→기록이 끝까지 동작했다(후보 1, J 82초, 검증 원인 0). 운영 시험 결과는 성과로 세지 않는다.
