## 3. 검증 digest·rewrite 구조 재사용 (K1)

v2.5에서만 요청 상태를 활성화한다. 도구 digest는 요청의 첫 실제 SHA 읽기를 내부 키에 재사용한다. metadata는 변경 감지 보조일 뿐 내용 검증의 대체물이 아니다. 기존 외부 manifest·compiler launch 검증을 유지하고, v2.5 내부 실행 경계에서도 도구 identity 변경을 거부한다. 비교 실행기는 각 요청 전후 실제 도구·J 바이너리를 다시 해시한다.

rewrite는 immutable SYM의 instance/signals 표와 template의 성공한 lazy 구문 분석만 보관한다. component와 entrypoint 구조는 분리하며 candidate·override·replacement 계획은 매번 계산한다. 실패를 미리 평가하거나 캐시하지 않아 첫 오류·대상 순서를 유지한다. 동적 계획·편집 바이트·첫 오류·같은 길이 도구 교체·요청 수명에 대한 Rust 테스트 4개가 통과했다.
